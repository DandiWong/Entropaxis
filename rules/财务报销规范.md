# 财务报销规范

适用于工作区内发票与报销凭据的自动检索、增量提取、智能分类、汇率折算、合规风控、排重归总与归档管理。

> 企业与环境参数（`<ReimbursementRoot>` 绑定、企业主体抬头与税号、合规阈值、政策真源）唯一真源为 [`.data/reimbursement-config.md`](../../.data/reimbursement-config.md)，本文件只含流程逻辑；分类规则见本文 4.1，属通用规则。

---

## 1. 目标与目录结构

所有发票与报销凭证统一归集于指定的报销工作根目录 `<ReimbursementRoot>`：

```
<ReimbursementRoot>/
├── YYYY-MM-DD/                          # 当日归总目录（按发票业务类型分目录）
│   ├── 交通/                             # 日常市内交通（日常通勤燃油、市内打车、地铁公交、日常停车通行）
│   ├── 差旅/                             # 出差差旅专项（按具体出差事由分行程子目录）
│   │   ├── YYYYMMDD-YYYYMMDD_{事由或地点}/ # 单次出差专包（如 20260624-20260626_北京CMAC大会）
│   │   │   ├── 酒店住宿发票及水单
│   │   │   ├── 机票 / 火车票 / 跨城客运发票及行程单
│   │   │   ├── 出差地当地网约车 / 出租车 / 燃油等差旅交通发票及行程单
│   │   │   └── 境外差旅外币汇率牌价截图（若涉及）
│   │   └── ...                          # 其他出差行程专包
│   ├── 通讯/                             # 手机话费充值、宽带网络、通讯运营商月结发票
│   ├── AI/                               # 模型 API、云算力平台、AI 订阅工具、云基础设施付费
│   │   ├── YYYYMMDD_InvoiceID_金额USD_服务商.pdf
│   │   └── YYYYMMDD_汇率牌价_USD_中国银行.png # 对应的消费当日牌价机构汇率截图（机构以配置为准）
│   ├── 餐饮/                             # 商务宴请、业务招待、日常外卖等餐饮服务发票
│   ├── 办公/                             # 办公耗材、文具用品、图书资料、软件许可、设备配件等
│   ├── 团建/                             # 团队建设活动、聚餐、团建场地租赁、文体拓展等专项
│   ├── 待处理/                           # 无法自动获取/解析的票据暂存（见 6.5），原文件名保留
│   ├── 其他/                             # 快递物流、公证认证等未单独列出的零星支出发票
│   └── 清单.md                           # 当日归总台账（含人民币/外币小计、汇率折算、合规预警与发票明细清单）
└── Archive/                              # 历史已报销归档目录（只读锁定）
    └── YYYY-MM-DD/                       # 报销流程审批或提报完成后整体移入
```

- **散落暂存处理**：用户手动放入 `<ReimbursementRoot>` 根目录下的发票，在下一次归总任务触发时自动识别、重命名并移动到当天的分类子目录中。

## 2. 触发、配置检查与增量判定

1. **配置完整性检查（报销初始化/报销指令前置）**：
   - 收到「报销初始化」或「报销」相关指令时，先检查 `.data/reimbursement-config.md` 是否存在：若不存在，创建含必填字段列表的空白 `.data/reimbursement-config.md`，然后进入交互确认流程补填必填字段；若存在，读取后逐项核对必填字段：`<ReimbursementRoot>` 绑定、至少一个企业主体（抬头 + 统一社会信用代码，支持多主体）、合规阈值（超期天数、汇率源）、政策真源。
   - 存在缺失时，Agent 从配置文件「候选检索来源」所列位置自行检索提取候选值；候选来源清单本身也是可移植参数，不在本规则中出现。
   - **缺失必须交互确认，禁止静默跳过**：发现缺失项后，不得仅在配置中保留 ❌ 标记就继续执行；必须先与用户完成一轮交互——逐项列出缺失字段、候选值及其来源，请用户确认或补填。
   - 用户确认后回写配置并继续；用户当场无法提供时，该项保留缺失标记、相关校验按「无法校验」在 `清单.md` 预警，并当次交互中告知影响后再继续。未经确认的推断值不得用于合规校验，不得虚构通过或失败。
2. **增量起始时间（Baseline）**：
   - 检索 `<ReimbursementRoot>/` 及 `<ReimbursementRoot>/Archive/` 中所有形如 `YYYY-MM-DD` 的历史目录。
   - 取其中的**最大日期**作为增量起始 Baseline（若无历史目录，则按用户指定范围或默认最近 30 天）。
3. **多数据源扫描范围**：
   - **本机短信/信息**：检索自 Baseline 以来接收的开票短信与下载链接，自动穿透解析并获取电子发票。
   - **本机邮件**：检索自 Baseline 以来包含发票、Invoice、账单关键字的邮件（含附件、第三方开票跳转页及电子账单）。
   - **本地暂存**：扫描 `<ReimbursementRoot>` 根目录下未分类的 PDF 与图片文件。

## 3. 提取、转换与排重规范

1. **格式标准**：
   - 核心凭证仅收录 **PDF** 与 **清晰发票图片**（PNG / JPG / JPEG / HEIC）。
   - 排除 XML、OFD（除非财务特别要求）、系统签名文件或纯说明性文本。
2. **纯 HTML 账单与收据**：
   - 邮件中无 PDF 附件但包含完整结算金额与明细的电子收据（如订阅账单、线上服务通知），自动渲染为标准 A4 尺寸的 PDF 凭据后归集。
3. **辅助行程单与凭据处理**：
   - 网约车行程报销单、航班行程单、酒店水单等作为报销辅助凭据保留，统一添加 `_行程单` 后缀存入对应分类目录。
   - 辅助凭证在 `清单.md` 中单独标注，**不计入发票总张数与发票总额**，防止虚增报销金额。
4. **两级排重机制**：
   - **一级排重（业务键）**：以 20 位数电发票号码 / 统一发票号码 / 国际 Invoice ID 为唯一标识排重。
   - **二级排重（文件特征）**：以文件内容 SHA-256 哈希值兜底校验。已在任何历史或 Archive 目录中存在的文件直接跳过。

## 4. 智能分类与差旅专包规则

### 4.1 核心分类映射

| 类别 | 范围与关键词特征 |
|---|---|
| **交通** | **日常市内交通**：市内加油、日常市内打车/客运服务费、市内公共交通、日常停车通行费 |
| **差旅** | **出差全流程专包**：异地酒店客房/住宿、机票、火车票、出差期间异地用车及燃油（详见 4.2） |
| **通讯** | *电信服务*、*信息技术服务*话费、移动通信费、宽带月结账单 |
| **AI** | 模型推理与 API 调用、GPU/云算力、AI 订阅、Cloudflare、AWS 等云基础设施付费 |
| **餐饮** | *餐饮服务*、*生产生活服务*餐饮、日常就餐、外卖餐饮、商务招待 |
| **办公** | 办公耗材、电脑外设配件、文具纸张、图书资料、办公软件授权、快递邮寄等 |
| **团建** | 团队建设费、团队文体活动、团建拓展聚餐、团建场地租赁等 |
| **其他** | 会议注册费、培训费、规费、其他未明确分类项目 |

### 4.2 差旅行程专包规则

由于日常交通与出差交通报销流程及标准不同，所有出差相关凭证必须按次归集到独立的行程专包中：

1. **专包目录命名**：
   `差旅/YYYYMMDD-YYYYMMDD_{出差事由或目的地}/`
   *(例: `差旅/20260624-20260626_北京CMAC大会/`)*
2. **专包收录原则（时间 + 地点联动）**：
   - **住宿凭据**：出差期间的酒店住宿发票及水单。
   - **大交通凭据**：往返出差城市的飞机票、铁路客票、城际客运发票及行程单。
   - **出差地交通**：在出差起止日期范围内、发生在出差当地的所有网约车、出租车、加油费等交通发票，**统一收拢到该差旅专包中，不得混入日常 `交通/` 目录**。

## 5. 外币 Invoice 与外汇牌价规范

凡涉及外币（USD、EUR、GBP、HKD 等）结算的 Invoice，必须同步配套汇率凭证并进行人民币换算：

1. **外汇牌价截图留存**：
   - 自动获取该笔消费**消费当日（开票日）**、配置文件汇率源对应机构的官方牌价页面截图。
   - 截图保存至该 Invoice 所在分类目录中，命名规范：
     `YYYYMMDD_汇率牌价_{币种}_{牌价机构}.png`
     *(例: `20260828_汇率牌价_USD_中国银行.png`，机构以配置汇率源为准)*
2. **汇率选用基准**：
   - 汇率源及回退链（中行折算价 → 现汇买入价 → 外汇交易中心中间价）以配置文件中的合规阈值为准。
3. **人民币换算公式**：
   $$\text{报销人民币金额 (元)} = \text{外币金额} \times \left(\frac{\text{折算价}}{\text{牌价公布单位}}\right)$$
   牌价公布单位以配置汇率源的公布口径为准（如中行折算价为每 100 外币兑人民币，则单位为 100）。

## 6. 企业级合规风控与特殊票据处理

1. **发票抬头与税号合规校验**：
   - 自动核对购买方名称及统一社会信用代码是否匹配配置文件企业主体清单中的**任一主体**（报销可能涉及集团/子公司多个主体）；均不匹配时按下一行规则处理。
   - 抬头不符、开具为个人名称或缺失税号的普票，文件名追加 `_待核抬头`，并在 `清单.md` 中标红提示 `⚠️ [待核实抬头]`。
2. **专票/普票及税额拆解**：
   - 自动提取增值税税率、税额与不含税金额。
   - 在 `清单.md` 中单独列明「发票类型（数电专票/数电普票/行程单）」及「税额」，方便财务系统直接录入进项税抵扣。
3. **红字冲减发票处理**：
   - 识别负数发票与冲红记录，文件名追加 `_红字冲减`。
   - 在汇总面板与明细中单独体现抵减项，并在合计金额中按负数扣减，防止虚增总账。
4. **辅助支付凭据与消费明细关联**：
   - 大额餐饮宴请、办公采购等附带的微信/支付宝付款截图、POS 小票或消费清单，统一命名为：
     `YYYYMMDD_发票号码_支付凭据.png` / `YYYYMMDD_发票号码_消费明细.pdf`
   - 与对应发票同目录存放并在清单中标注关联，但不重复计入发票张数。
5. **开票超期与跨年预警**：
   - 自动核验开票日期，对超过配置文件中超期阈值或跨会计年度的发票，在 `清单.md` 中标注 `⚠️ [发票超期预警]`，提示优先报销或走特殊审批。
6. **政策真源**：
   - 本规则合规标准与公司政策文件冲突时，以配置文件中列出的政策真源为准。

## 6.5 异常降级与人工介入

无法自动完成获取或解析的票据，不阻塞归总任务，统一降级处理：

- **适用情形**：短信开票链接失效/过期、汇率牌价页面不可访问、发票图片模糊无法可靠 OCR、境外 Invoice 缺失可解析的 Invoice ID 等。
- **降级动作**：原文件（或线索截图）保留原文件名移入当日目录 `待处理/`；无文件仅有线索的，在 `清单.md` 中记录线索来源。
- **台账呈现**：在异常与合规预警面板单列 `⚠️ [待处理]` 条目，注明失败环节（获取/解析/汇率/OCR），待人工补齐后随下一次归总任务重新归集。
- 汇率牌价获取失败的外币 Invoice：先按降级路径入 `待处理/`，不得跳过汇率凭证直接折算入账。

## 7. 文件命名规范

所有发票与凭证统一按以下规范重命名：

- **国内数电/电子发票**：
  `YYYYMMDD_发票号码_金额元_销方简称.pdf`
  *(例: `20260828_26317000003101318781_281.88元_中国石化.pdf`)*
- **国际 / 境外 Invoice**：
  `YYYYMMDD_InvoiceID_金额币种_服务商.pdf`
  *(例: `20260828_IN-76944775_160.00USD_Cloudflare.pdf`)*
- **汇率牌价凭据**：
  `YYYYMMDD_汇率牌价_币种_中国银行.png`
  *(例: `20260828_汇率牌价_USD_中国银行.png`)*
- **行程单与辅助凭证**：
  `YYYYMMDD_发票号码_平台名称_行程单.pdf`
  *(例: `20260828_26317000003104074706_滴滴出行_行程单.pdf`)*
- **支付凭据 / 消费明细**：
  `YYYYMMDD_发票号码_支付凭据.png` / `YYYYMMDD_发票号码_消费明细.pdf`
- **红字冲减发票**：
  `YYYYMMDD_发票号码_负金额元_销方简称_红字冲减.pdf`

## 8. 交付台账与验证自检

每次发票归总完成后，必须在当日目录 `YYYY-MM-DD/` 下自动生成 `清单.md`：

1. **台账结构**：
   - **汇总面板**：
     - 发票总张数（专票张数 / 普票张数 / 境外 Invoice 张数）。
     - 各分类小计（含差旅各行程专包小计）。
     - 国内发票合计（价税合计、不含税金额、税额）。
     - 境外外币发票原币合计及按配置汇率源折算价换算后的人民币金额。
     - **最终报销总折合人民币金额**（国内发票价税合计 + 外币折算人民币金额 - 红字冲减金额）。
     - **异常与合规预警面板**（超期发票、待核抬头发票清单）。
   - **发票明细清单**：表格列出序号、开票日期、类别（注明所属差旅专包）、发票号码/ID、发票类型、开票方/服务商、原币金额、折算价、报销人民币金额、税额、汇率/关联凭证、文件名、合规状态。
   - **辅助凭证清单**：列出行程单、支付凭据等辅助凭据对应的发票与文件。
2. **完成前自检**：
   - 提取的 PDF / 图片 100% 可正常打开与解析。
   - 发票号码、原币金额、税额与票面信息完全一致。
   - 外币 Invoice 均已配齐对应的中行外汇牌价截图，且折算金额计算无误。
   - 日常交通与差旅专包边界清晰，无混放与重复文件。

## 9. 归档生命周期与状态流转

1. **归档锁定（Archive）**：
   - 当某批次报销流程提报或审批完成后，由用户手动或指令将对应的 `YYYY-MM-DD` 目录整体移入 `<ReimbursementRoot>/Archive/`。
   - `Archive/` 目录为**只读锁定状态**，后续增量归总任务仅读取其发票号码与 SHA-256 哈希用于排重，严禁修改或移出其中的文件。
2. **重报与打回处理**：
   - 若某批次报销被财务驳回需要调整，将该目录从 `Archive/` 移回 `<ReimbursementRoot>/` 根目录。
   - Agent 再次运行时会自动识别该目录，重新执行校验并输出更新后的 `清单.md`。
