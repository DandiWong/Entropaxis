# 技能设计

Skill 的设计原则、渐进式披露、元数据与工作流规范。形态判定见 [`知识沉淀.md`](知识沉淀.md)「沉淀形态判定模型」；Tool 设计见 [`工具设计.md`](工具设计.md)。Skill 的配置与凭证由 Skill 自管（见 2.2）；生成办公文档或图片的 Skill，尾部须包含《文件交付》第 4 节的打开闭环（按 2.2 的可选增强方式接入）。

## 1. 设计原则

### 1.1 克制与 Token 预算
- Skill 正文与系统提示词、对话历史、其他 Skill 元数据共享上下文窗口；只写模型尚不具备的领域专有上下文，不解释通用编程或文件常识。
- 对每句话自问：模型真的需要它吗？值得它的 Token 成本吗？
- 冷启动只预加载 Frontmatter（`name` 与 `description`），正文触发后才读取。
- 数据检索、结构化校验或文件提取优先交给内置脚本，只向上下文返回紧凑字段。

### 1.2 自由度阶梯匹配
按任务的脆弱性与可变性设定指导自由度：
1. **高自由度（启发式）**：多种解法均有效、强依赖上下文（代码审查、设计评估）；写要点清单与评估维度。
2. **中自由度（参数化模板）**：有首选模式但允许定制（特定格式报告、配置生成）；写可填空模板、伪代码或带参数脚本。
3. **低自由度（确定性脚本）**：易错、必须按序、零容错（数据迁移、发布、字节级导出）；写精确命令，并声明"不得修改参数或跳步"。

## 2. 渐进式披露架构

### 2.1 单跳引用与 500 行预算铁律
- `SKILL.md` 正文控制在 500 行以内，只作概览与导航。
- 参考资料从 `SKILL.md` 直接链接（深度为 1），严禁 `SKILL.md → A.md → B.md` 式嵌套，防止部分读取时丢失上下文。
- 超过 100 行的 `references/*.md` 顶部须有目录，便于切片读取。

### 2.2 自包含目录与独立运行
```text
<skill-name>/
├── SKILL.md       # [必选] 触发条件、概述与步骤（≤500 行）
├── CHANGELOG.md   # [必选] Keep a Changelog 版本记录
├── references/    # [可选] 领域规范、API 说明、词表（单跳引用）
├── templates/     # [可选] 可填充模板
├── config/        # [可选] 本机实例配置（不入分发包）
└── scripts/       # [可选] 供执行而非阅读的脚本
```
- **可分发边界**：可分发 Skill 的正文、元数据与内置资产不得引用工作区专属 `.entropaxis/data/` 声明、内部项目目录、绝对路径或仅内部可访问的定位信息；运行所需资产随包内置。
- **对根系统零依赖（独立运行铁律）**：Skill 须能脱离本工作区独立运行，因此不得把 `.entropaxis/` 写成运行前置：
  - 不调用 `.entropaxis/tools/<name>.py` 作为必需步骤；
  - 自身脚本路径相对自身目录定位（如 `<skill-dir>/scripts/x.py`），不写 `.entropaxis/skills/<自身名>/…`；
  - `.entropaxis/rules/` 正文只作「在本工作区运行时的判据出处」，缺失时按 Skill 自身正文执行。
  - **工作区能力按可选增强接入**：落盘打开等能力（`open_file.py`）由 `.entropaxis/` 单点掌管，Skill 不自建第二份实现、也不硬依赖——存在即调用，不存在就回报产物绝对路径由用户自行打开。
- **配置与凭证自包含**：Skill 不读写 `.entropaxis/data/` 下任何文件。实例配置放 Skill 自身目录（如 `<skill-dir>/config/`）；凭证用环境变量或用户级目录（如 `~/.config/<skill-name>/`，Windows `%APPDATA%\<skill-name>\`），不写进工作区。需要项目、看板等外部事实时，向其真源系统查询（CLI/API），不读控制面注册表。
- **控制面 Skill 例外**：以 `.entropaxis/` 自身为作业对象的 Skill（脚手架、工具锻造、控制面审计）不参与独立分发，在 frontmatter 声明 `metadata.scope: control-plane` 后豁免本条；该声明即唯一登记处。
- **不可分发 Skill 的自封装排除**：承载组织专属流程、内部端点或业务口径的 Skill，在其目录内放一个内容为 `*` 的 `.gitignore` 整体排除，不在公共版本库留私有清单。这类 Skill 的触发词只写在自身 `description`，控制面规则与根路由不为其设入口。
- **分发信道唯一**：`.entropaxis/` 对外分发只走 `git clone` / `git archive` / 版本库 ZIP，严禁整目录拷贝、压缩或网盘同步——被排除的私有 Skill 仍在文件系统上。

### 2.3 Skill 分发包

用户明确说"分发 / 打包 / 导出 `<skill-name>` skill"时执行本节；只生成本地 ZIP，不发送、发布或上传。

1. **先审计再暂存**：定位 `.entropaxis/skills/<skill-name>/`，依据 `SKILL.md` 的工作流、脚本导入与资产引用建立分发清单；在临时目录组装，不压缩整个工作区或父目录。
2. **只纳入运行必需内容**：`SKILL.md`、`CHANGELOG.md`、运行直接引用的 `references/`、`templates/`、`scripts/`，以及依法须保留的上游许可证。测试、样例、生成器、构建产物、日志、旧归档与本机配置（`config/`、`output/` 等）不入包。
3. **硬性排除**：`.git/`、`.entropaxis/data/`、凭证、绝对路径、`__pycache__/`、`*.pyc`、`node_modules/`、编辑器/系统缓存或其他实例文件。无法判定是否运行必需时保留并在交付中说明。
4. **归档契约**：生成与 Skill 目录同级的 `<skill-name>.zip`，顶层仅含 `<skill-name>/`；"分发"指令即覆盖同名本地归档的授权。创建后核验可读、顶层目录正确且无第 3 条排除项。
5. **物理交付**：核验通过后按《文件交付》第 4 节用 `open_file.py` 打开 ZIP 所在目录；回复写明归档路径、校验结果和未纳入的类别。

## 3. 元数据与发现

- **`name`**：小写字母、数字和连字符，≤64 字符，用动宾或名词短语（如 `ppt-design`、`tool-crafter`）。
- **`description`**：第三人称（如 `"Generates executive presentations..."`，不写 `"I can help..."`），同时写明做什么与何时触发（意图关键词、文件后缀），≤1024 字符。

## 4. 工作流与反馈闭环

- **进度清单**：多阶段任务在 `SKILL.md` 中提供可复制到对话逐项打勾的清单（`- [ ] Step 1: …`）。
- **质量门禁**：每个阶段写明通过/失败判据；失败时写明回退步骤。
