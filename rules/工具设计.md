# 工具设计

Tool 的准入判据、接口契约与工程治理。形态判定（该做成 Rule/Tool/Skill/Schema/Script）见 [`知识沉淀.md`](知识沉淀.md)「沉淀形态判定模型」；Skill 设计见 [`技能设计.md`](技能设计.md)；纯标准库、零系统绑定、凭证隔离等红线分别见 [`01_根系统治理.md`](01_根系统治理.md) 与 [`控制面布局.md`](控制面布局.md)。

## 1. 工具化候选的四类信号

Agent 在日常开发、复盘与系统治理中，通过扫描以下 4 类信号识别潜在工具化候选：

1. **高频复合终端命令**：会话中频繁出现 3 步以上长管道命令（如 `find | grep | awk | sed`、复合 git log 处理），跨平台语法脆弱；
2. **规则中的机械硬算**：规则中描述了大量路径深度、正则校验、Front Matter 回填等纯机械步骤，耗费 Token 且易漂移；
3. **模型易出错的精确计算**：涉及 SHA-256 计算、字节精确比对、AST 语法检查等，大模型难以保证字符级精确；
4. **高危易扩散的破坏动作**：涉及批量清理、状态重置，需收敛为受控参数 API 防范破坏。

## 2. 工具化五维准入漏斗

必须同时满足以下 5 项硬性判据方可准予转化为 Tool：

- **1. 确定性**：纯确定性计算/格式校验（淘汰: 依赖主观审美与复杂语义理解）
- **2. 复用频次**：跨 2 个以上项目复用或核心工作流高频刚需（淘汰: 单点一次性修复）
- **3. 安全收敛**：将危险 Shell 收敛为受控白名单 CLI（淘汰: 仍需完全开放任意执行）
- **4. Token 收益**：1 行 Tool 调用替代 50+ Token CoT 或扫表，单行最小高密度返回（淘汰: 极微小命令）
- **5. 零系统绑定**：纯 Local-First 标准库实现，配置声明外置（淘汰: 强依赖远程商业私有 API）

## 3. 接口契约

1. **语义化 CLI 契约**：采用 `动词_名词.py` 命名，`argparse` 标准自省参数与前置清洗；
2. **行动导向的错误契约**：报错严禁仅抛裸异常堆栈，必须输出 `❌ 错误原因` + `👉 修复建议`（明确指导 Agent 如何自愈修改参数）；
3. **结构化输出**：标准输出（stdout）必须为纯 JSON 或固定 Key-Value 分段纯文本，杜绝无意义废话；
4. **原子组装与幂等性**：新建/写入类工具必须在 `tempfile.TemporaryDirectory` 中原子组装校验，全部通过后再原子替换，支持幂等重入。
5. **结构化状态外置**：机器要判定的状态（枚举、版本号、指纹、终态标记）不得寄生在人工自由编辑的 Markdown 正文里，须拆到独立的结构化 sidecar（JSON/YAML，配 Schema 校验）；正文只做叙事引用，不承载判定字段。判定逻辑若已在为"文本变体"（大小写、全角符、隐形字符、重复键）加正则，是这条被违反的信号，换载体而非再加一层解析；
6. **Token 经济性优先**：工具输出必须面向极小上下文消耗设计，遵循默认静默原则（Silence is Golden），只报最终结论不打过程流水账；默认返回单行极简高密度纯文本（~15 tokens）并支持 `--json`；可能返回长列表的工具必须内置默认截断（如 limit=20）与分页，杜绝排版废话与无意义填充。

## 4. 机制转 Tool 六步闭环

```text
Step 1: 契约设计 (Spec)     ➔ 定义参数列表、输入输出 Schema 与行动导向错误自愈指引
Step 2: 标准库实现 (Code)   ➔ 编写 .entropaxis/tools/<tool_name>.py（纯标准库 + 原子暂存）
Step 3: 测试驱动验证 (TDD)  ➔ 编写 .entropaxis/tests/test_<tool_name>.py（覆盖正常与异常分支）
Step 4: 双重体检门禁 (Lint) ➔ 运行 unittest（100%通过）与 lint_workspace.py（编译与体检全绿）
Step 5: 路由装配 (Wire)     ➔ 在调用它的规则或 Skill 正文写明调用命令；可选在 tips.md 追加一条使用提示（须用户确认）
Step 6: 交付验证 (Verify)  ➔ 按《软件工程》「检查按影响选」给出检查对象/证据/结论/未覆盖范围
```
