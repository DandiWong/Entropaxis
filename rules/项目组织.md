# 项目组织

项目边界、归属判据与跨会话事实沉淀。目录结构清单、`RawInput/` 整理映射与 `docs/` 布局见 [`project-layout`](../skills/project-layout/SKILL.md) Skill；文件命名、Front Matter 与落盘打开见 [`文件交付.md`](文件交付.md)。

## 系统与项目

- `.entropaxis/` 只放通用规则、模板、初始化工具和系统专用 Skill。
- 每个项目放在系统工程之外，默认与系统工程同级。
- 不按需求、POC、Spec、交付等固定阶段预建目录。

## 工作区项目索引

**唯一真源**：`.entropaxis/data/templates/registry.md`（工作区实例数据，不分发）。需要项目 ID、主目录或口语关键词时先读它；共享资料层目录（不属于外部看板项目）以 [`.entropaxis/data/templates/workspace-config.md`](../data/templates/workspace-config.md) 为准。

`.entropaxis/data/templates/registry.md` 不存在时，先创建空白文件（保留表头与列定义）并提示用户补填，再继续任务；不得以「未找到注册表」为由跳过项目解析。

## 事务胶囊

有真实事件、特性研发或交付物时，统一创建 `YYYYMMDD_[甲方&乙方_]主题/` 容器目录。

- **先查后建与收敛铁律**：落盘前必须先检索当前上下文/当前日期是否已存在同主题谱系的既有胶囊；同一事件演进中的调研、方案、原型、Spec、审计、复盘与多份分析报告**必须全生命周期收敛于同一胶囊目录**，按 `序数_类型.ext` 递增落盘，**严禁在同日反复新建平行的碎片兄弟目录**。胶囊内文件名不带主题名，主题与上下文在 Front Matter 声明。
- **单体容器准入边界**：仅当任务为确定的一次性孤立交付（单份纪要/独立PPT）且无前序胶囊时方可单文件建壳；一旦产生延伸产物立即就地收敛为多阶段胶囊管理。
- **子目录懒创建铁律**：胶囊内任何子目录（`00_原始素材/`、`assets/`、`prototypes/`）**只在确有具体材料落盘时创建**，严禁按目录树预建空壳占位。材料少时直接平铺在胶囊根；材料明显变多再分子目录。
### 双层流转：胶囊过程态与全局主干真源

- **事务胶囊层**：特性研发全生命周期完整上下文，随项目永久留存与回溯（去向: 胶囊目录内）
- **全局主干层**：
  - 拍板生效的 1 句话核心基线（超链回 `02_方案.md`）➔ `01_项目管理/DECISIONS.md`
  - 源码与测试 ➔ `03_工程研发/<app>/src/`、`test/`
  - 细粒度变更与规划真源 ➔ 代码库根目录或集中收敛于 `docs/00_project/` 的 `Tasks.md`、`Changelog.md`、`Benchmark.md`（链接不复制）
  - 任务状态翻转 `done` ➔ 任务看板与台账

## 决策与基线底册

`01_项目管理/DECISIONS.md` 是项目跨会话、跨 Agent 的唯一当前事实真源，也是持久记忆层——**没有落盘的决策等于没有记住**，下一次会话或换一个 Agent 就会丢失。

- 只写已确认或当前明确采用的内容（业务基线、核心架构选型、接口标准、排除范围），每项链接到时间线中的证据或产物。
- **触发点**：用户明确表态「就这么定 / 确认 / 采用 X」、评审形成结论、机制或口径敲定、选型拍板。纯讨论、假设、候选方案不落盘，放「待确认/待决事项」，不冒充当前事实。
- 新结论覆盖旧结论时更新当前状态；旧版本留在原事件目录，保留可追溯演进。
- 存量项目**首次出现确认决策**时才创建该文件，不预建空文件。
- 不使用 `node`、`handoff_to`、`fields_origin` 或统一状态机。只有法规、验收或正式审批确有要求时，才增加独立契约文件。

## Agent 工作闭环

1. 读根 `AGENTS.md` 常驻层，按任务路由表按需读取规则与项目导航文档。
2. 把用户自然语言解析为任务卡（见 [`指令解析.md`](指令解析.md)），并用项目文件、看板、日历和素材查证。
3. 确认本次事件目录和目标。
4. 在事件目录中处理材料。
5. 更新 `README.md` 与 `DECISIONS.md` 中发生变化的部分；确认决策落盘。
6. 需要登记任务时按看板操作技能标准同步，并重新读取验证。
7. 报告产物位置、确认项、未决事项、下一步和同步结果。

## 与看板的边界

- 项目目录保存材料、产物、时间线、结论、基线和知识；看板保存执行任务、状态、截止日期、相关人及通知状态。
- `DECISIONS.md` 记**当前以什么为准**（事实/决策/基线/口径），看板记**任务/状态/截止/相关人**，两者不重复；`DECISIONS.md` 的「下一步」只记高层方向或关键事件。
- 看板读写统一经看板操作技能（本地 CLI + Bearer Token）；不手写 HTTP 请求，不走本地端口或公开 Tunnel。
- 新任务必须带稳定 `source_ref`（格式与幂等行为见看板操作规范）。
- 对话中的结论、知识或材料不自动转成任务；只有明确行动项才进入看板。安排会议只有在用户明确要求时才写入日历。
