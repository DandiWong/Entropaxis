# 开发任务联动规则

适用于使用本地任务文档、task Spec、Board-Platform 和 Dashboard 的开发项目。项目通过 `docs/.board.json` 显式启用；未配置的项目不自动创建外部记录。

> **工具说明**：Board-Platform 是工作区采用的项目任务管理工具（CLI：`board-platform`）；Dashboard 指由 `internal-board` Skill 管理的统一任务看板（`dash.py` + Bearer Token）。

## 唯一身份与状态真源

- 每个任务使用稳定 ID；新 ID 默认采用 `Req-N`、`Tech-N`、`Task-N` 或 `Bug-N`，各前缀独立递增。
- 历史 ID 保持原样，不批量重排或复用。
- 项目统一采用 `Tasks.md`（大写 PascalCase）作为本地任务与需求规划唯一真源（融合 TODO/Backlog）；不得同时维护多套任务状态。
- Spec 保存身份、设计和验收条件，不另存任务状态。

同一 ID 对应：

| 位置 | 约定 |
|---|---|
| 本地任务文档 | 标题或条目包含任务 ID，并保存当前状态 |
| Spec | `docs/04_architecture/specs/<ID>_<Topic>.md`，front matter 含 `id` |
| Board-Platform | 标题以 `[ID]` 开头 |
| Dashboard | `source_ref = <dashboard_project>:<ns>:<ID>` |

## 项目绑定

`docs/.board.json` 的最小字段：

```json
{
  "dashboard_project": "iit_publication",
  "board-platform_project": "完整 UUID",
  "ns": "PaperPro"
}
```

其他平台字段可以保留，但当前 `sync_board.py` 只同步本地任务、Board-Platform 与 Dashboard，不应声称已同步未实现的平台。

Spec front matter 示例：

```yaml
---
type: Spec
id: Tech-2
title: Example Topic
project: PaperPro
generated: { by: human:user, at: 2026-08-27 }
---
```

front matter 只保存静态身份和来源；状态留在本地任务真源。

## 状态映射

| 语义 | 本地 | Board-Platform | Dashboard |
|---|---|---|---|
| 待办 | 未勾选 / plan | `todo` | `plan` |
| 进行中 | active | `in_progress` | `active` |
| 待评审 | review | `in_review` | `review` |
| 完成 | 已勾选 / done | `done` | `done` |
| 归档 | archived | `done` | `archived` |
| 暂不做 | backlog | `backlog` | 不创建或按项目约定处理 |

## 同步工具

从工作区根目录运行：

```bash
python3 .system/tools/sync_board.py <项目根> \
  --spec docs/04_architecture/specs/Tech-2_ExampleTopic.md \
  --status active
```

也可使用 `--task`、`--title` 或 `--stdin`；以脚本 `--help` 为当前参数真源。工具按任务 ID 和 `source_ref` 幂等更新，不手写 HTTP 请求。

## 闭环

1. 开始任务：确认本地状态真源和 Spec；项目已启用联动且获得相应授权时同步为 `active`。
2. 设计变化：更新 Spec 后重跑同步，使 Board-Platform 描述与 Spec 一致。
3. 完成任务：先完成项目验证和本地状态更新，再同步为 `done`。
4. 同步后回读结果；任一端失败时明确报告，不把部分成功写成全部完成。

项目 `AGENTS.md` 只链接本规则并声明本地状态真源、绑定文件和项目特有闭环，不复制本规则正文。
