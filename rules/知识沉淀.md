# 知识沉淀

## 沉淀形态判定模型

沉淀任何经验、结论、资料或能力时，按**时效属性**与**作用机制**在七种形态中选择唯一主形态，严禁形态错位，也不得无差别生成碎片文档：

- **落为新文档**：离散历史事实/交付物（纪要/调研/PRD/汇报/报告）· 归属: 遵循《文件交付》容器化目录铁律，或 `_知识库/项目资料/` · 写入即冻结
- **更新旧文档**：演进中唯一事实/基线（决策/口径/范围/架构/模型/约束）· 归属: `DECISIONS.md`、`README.md`、`_知识库/index.md` · 持续覆写
- **落为规则 (Rule)**：长期行为约束/安全红线/裁决标准/防错/文风 · 归属: 根 `AGENTS.md` / `.entropaxis/rules/` · 跨任务常驻或路由
- **生成 Skill**：多阶段复合 SOP/交互引导/模板渲染/校验门禁 · 归属: `.entropaxis/skills/<name>/` · 独立封装按需激发
- **转为 Tool**：纯确定性算法/机械 I/O/安全收敛 CLI/体检脚本 · 归属: `.entropaxis/tools/<name>.py`（纯标准库）· 幂等可重入
- **声明 Schema**：结构化契约（字段集/取值域/必填项）· 归属: `.entropaxis/schemas/<name>.schema.json` · 机械校验
- **局部 Script**：单项目专属一次性数据修复/迁移脚本 · 归属: `03_工程研发/<app>/scripts/` · 用后即弃

**生成 Skill 的触发意图**：用户输入 `落成skill`、`做成skill`、`封装成skill`、`沉淀为skill`、`写个skill`、`做成技能`、`做成一个技能` 等。先按上表判定形态是否确为 Skill（不满足则转 Rule 或 Tool），再按 [`技能设计.md`](技能设计.md) 设计与实现。

### 沉淀门禁与反面模式
- **落盘授权不重复定义**：独立文档是否获准创建统一遵循 [`文件交付.md`](文件交付.md) 第 1 节；本规则只决定沉淀形态、归属和生命周期。
- **严禁碎片副本**：发现架构或决策变化，直接修改真源文件，严禁新建 `v2.md`、`新版方案.md` 等冗余副本。
- **一步直达**：判定形态后直接写入目标真源，禁止生成 `待沉淀.md` 等中间过渡文件。

## 讨论沉淀文档结构

经充分讨论后落盘的调研、方案、问题排查、缺陷修复记录等文档，按以下结构组织：

1. **主题与场景**：讨论对象和具体触发事件；
2. **Baseline**：讨论开始时公认的现状、口径或参照基线，附来源链接；
3. **问题**：本次要解决的问题及其与 Baseline 的偏差；
4. **原因**：经查证的原因；未查明时明确写“原因未查明”；
5. **解决方案**：已确认方案、关键取舍及落选理由；
6. **遗留问题**：未决事项、待确认项和后续动作；已拍板决策同步至 `01_项目管理/DECISIONS.md`。

### 连续审计事件生命周期

- 同一目标谱系、同一审计目标且尚未终审通过，视为同一审计事件；连续复审只维护一份审计报告，逐轮记录受审对象指纹、结论、问题关闭情况与新增问题，不另建版本副本。
- **终审判据与人工锚点**：判据、Critical 人工签字与轮次上限/僵局升级规则统一见 `角色协作.md` 方案审修协同闭环，本节只声明生命周期边界，不重复操作细节。
- 终审通过后冻结该报告；后续目标或审计目标发生变化时，新建审计事件并引用前序报告。
- 详细执行 SOP 由 `artifact-audit` Skill 负责，规则层不复制模板或操作步骤。


## 联邦知识库原则（跨项目知识治理）

### 按作用域归属唯一层级

知识按**主题作用域**归属唯一层级，不按「谁用它」归属：
- 项目独有事实 → 项目 `_知识库/`
- 跨项目事实 → 工作区/领域 KB（共享资料层目录清单以 [`.entropaxis/data/templates/workspace-config.md`](../data/templates/workspace-config.md) 为准）
- 用到别层 → 在 `_知识库/index.md` 引用，**不复制**

### 联邦薄索引

各层 KB 各有一份薄 `index.md`（与 AGENTS.md 路由思路同构，渐进加载）。工作区根 `_知识库/index.md` 向下路由到领域/项目 KB，按需生成：默认手动维护，已安装知识库/看板 Skill 时由该 Skill 自带的索引同步能力承担（触发条件：首个真实 `_知识库/index.md` 落地且出现跨项目检索需求）。

### 四套记忆系统边界

- **仓库内 Markdown**：项目与工作区唯一知识真源（**是**）
- **Nowledge Mem (`nmem`)**：个人跨工作区缓存/搜索 · 否（加速与临时）
- **Claude `memory/`**：会话级用户/项目记忆 · 否（会话辅助）
- **graphify 图**：跨层语义检索 · 否（派生加速，可重建）

严禁将加速层（nmem、graphify-out/）写入当作事实来源；删了可重建。

### 图为派生

**SSOT = 仓库内 Markdown**：可 diff、可审计（医药合规必需）、可迁移。graphify / nmem 为可重建的派生加速层，永不权威。派生物目录（`graphify-out/`、`.nmem/`）加入 `.gitignore`，不污染真源。

## 双层知识

项目知识分为：

- **项目独有资料**：默认归档在 `_知识库/项目资料/`。
- **共享资料**：保存在项目上层的公司、部门或个人知识库中，项目只在 `_知识库/index.md` 引用。

共享知识库可以是普通文件目录，也可以是 LLM-Wiki。项目不复制整套共享知识库。

## 何时独立归档

以下资料放入项目知识库：

- 只属于本项目的客户、研究、方案或解释材料；
- 项目交付时必须随项目移交的依据；
- 外部路径可能失效的关键证据；
- 必须冻结特定版本的法规、标准、制度或模板。

公共模板、公司制度、通用行业规范和跨项目知识默认只引用。

## 索引要求

`_知识库/index.md` 至少记录：

- 名称；
- 文件或上层路径；
- 来源和版本日期；
- 在本项目中的用途；
- 是否需要冻结版本。

普通资料不要求 checksum、jurisdiction、抽取状态等字段。法规、标准或受控文件确有版本审计要求时再补充。

## Agent 边界

- 不移动、覆盖或修改共享资料。
- 未经确认，不把共享敏感资料复制进项目。
- 综合知识必须链接原始依据，并区分来源事实和 Agent 推断。
- 只有实际需要全文检索时才生成 Markdown 抽取文本。
