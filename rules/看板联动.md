# 看板联动

适用于使用本地任务文档、task Spec 及外部看板系统（如 Linear、Jira、飞书、GitHub Projects、团队自研看板等）的开发项目。

> **设计原则（Local-First & 零系统绑定）**：
> 1. **本地真源**：项目内 `Tasks.md` 与 Spec 永远是状态第一真源；没有外部看板时，工作区功能必须 100% 完整可用。
> 2. **外部看板是镜像层**：外部看板作为对外展示、跨团队协同与状态镜像端，通过参数化配置按需挂载。
> 3. **平滑降级**：外部看板未配置或离线时，本地任务推进不受任何阻断。

## 唯一身份与状态真源

- 每个任务使用稳定 ID；新 ID 默认采用 `Req-N`、`Tech-N`、`Task-N` 或 `Bug-N`，各前缀独立递增。
- 历史 ID 保持原样，不批量重排或复用。
- 项目统一采用 `Tasks.md`（大写 PascalCase）作为本地任务与需求规划唯一真源（融合 TODO/Backlog）；不得同时维护多套任务状态。
- Spec 保存身份、设计和验收条件，不另存任务状态。

同一 ID 对应关系：

- **本地任务文档**：标题或条目包含任务 ID，并保存当前状态
- **Spec 规格**：`docs/YYYYMMDD_主题/04_Spec_<ID>.md`（独立 Spec 用 `<ID>_中文主题.md`），Front Matter 含 `id`
- **开发过程看板 (Dev)**：标题或条目以 `[ID]` 开头
- **团队/主看板 (Main)**：幂等键 `source_ref = <project_id>:<ns>:<ID>`
## 项目绑定

项目通过 `docs/.board.json` 显式声明外部看板映射，最小结构：

```json
{
  "ns": "ProjectNamespace",
  "boards": {
    "main": "main_project_id",
    "dev": "dev_board_uuid_or_id",
    "ext": "space_name_or_id"
  }
}
```

> **兼容与 Provider 声明**：平滑兼容平铺形式（如 `"main_project": "..."`、`"dev_project": "..."`）。各角色用哪个 Provider CLI 由看板 Skill 自带（控制面不登记）；CLI 未安装或不可用时，工具自动降级为纯本地，不阻断任务推进。凭证只走环境变量或用户级目录，不进配置文件和命令行参数。

### Provider 四态结果契约

同步工具区分四种结果，不折叠为二值：

- **`FOUND`**（目标已存在）：走更新分支，不创建第二个
- **`NOT_FOUND`**（目标确不存在）：只创建一次并回读确认
- **`FAILED`**（查询/写入失败）：不创建，上报 `error` 原文
- **`UNKNOWN`**（超时或响应丢失）：先按稳定回读键查询是否已完成，再决定下一步，不盲目重试创建
结构化结果至少含 `status`、`id`、`error`、`retryable`、`cursor`；退出码非 0、`OSError`、无效 JSON 归 `FAILED`，`TimeoutExpired` 归 `UNKNOWN`。列表查询遍历 `cursor` 直到耗尽，不只取单页。

**回读键按端选择**（不假定所有 Provider 都有 `source_ref`）：

- **Main（团队主看板）**：稳定回读键 `source_ref`
- **Dev（开发过程看板）**：稳定回读键为 issue 标题前缀 `[<TaskID>]`
Spec front matter 示例：

```yaml
---
type: Spec
id: Tech-2
title: Example Topic
project: ProjectNamespace
generated: { by: human:user, at: 2026-08-27 }
---
```

front matter 只保存静态身份和来源；状态留在本地任务真源。

## 状态映射

- **待办**：`Tasks.md`: 未勾选/`plan` · Dev: `todo`/`backlog` · Main: `plan`/`open` · Ext: `未开始`/`待处理`
- **进行中**：`Tasks.md`: `active` · Dev: `in_progress` · Main: `active` · Ext: `进行中`/`处理中`
- **待评审**：`Tasks.md`: `review` · Dev: `in_review` · Main: `review` · Ext: `待评审`/`审核中`
- **完成**：`Tasks.md`: 已勾选/`done` · Dev: `done`/`closed` · Main: `done`/`closed` · Ext: `已解决`/`已完成`
- **归档**：`Tasks.md`: `archived` · Dev: `archived`/`closed` · Main: `archived` · Ext: `已归档`
- **暂不做**：`Tasks.md`: `backlog` · Dev: `backlog` · Main: 暂不创建或标记挂起 · Ext: `暂缓`
## 同步执行体

`.entropaxis/` 只声明上面的身份、四态结果契约与回读键；**同步动作本身由已安装的看板 Skill 承担**（参数与命令见其自身 `SKILL.md`），按任务 ID 与 `source_ref` 幂等更新。

未安装看板 Skill、未声明 Provider 或 CLI 不可用时，按本规则设计原则第 3 条纯本地推进，不阻断、不报错。

## 闭环

1. **开始任务**：确认本地状态真源和 Spec；项目已启用外部联动且获得授权时同步为 `active`。
2. **设计变化**：更新 Spec 后重跑同步，使外部看板描述与 Spec 一致。
3. **完成任务**：先完成项目验证和本地状态更新，再同步为 `done`。
4. **对账与回读**：同步后回读结果；任一端失败时明确报告，不把部分成功写成全部完成。

项目 `AGENTS.md` 只链接本规则并声明本地状态真源、绑定文件和项目特有闭环，不复制本规则正文。
