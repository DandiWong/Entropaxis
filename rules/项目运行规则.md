# 项目运行规则

## 系统与项目

- `00_系统工程/` 只放通用规则、模板、初始化工具和系统专用 Skill。
- 每个项目放在系统工程之外，默认与系统工程同级。
- 不按需求、POC、Spec、交付等固定阶段预建目录。

## 时间线

- 有真实事件时创建 `YYYYMMDD_事件名/`。
- 材料少时直接平铺；材料明显变多后再建立 `原始材料/工作稿/定稿/`。
- 同一事件可以同时产生需求、评测、计划、培训或汇报材料。
- 不为了满足结构而创建空事件目录。

## 项目总览

`_项目总览.md` 只承担导航：

- 项目身份、用途、目标和相关人员；
- 按日期排列的事件索引；
- 当前有效状态入口；
- 最新产物和下一关键事件。

事件完成后追加或更新一行，不在总览中复制详细正文。

## 当前状态

`_契约/当前状态.md` 是项目唯一的当前事实：

- 只写已经确认或当前明确采用的内容；
- 每项基线链接到时间线中的证据或产物；
- 新结论覆盖旧结论时更新当前状态，旧版本仍留在原事件目录；
- 未确认内容放在“待确认”，不冒充当前事实。

不使用 `node`、`handoff_to`、`fields_origin` 或统一状态机。只有法规、验收或正式审批确有要求时，才增加独立契约文件。

## Agent 工作闭环

1. 读取 `AGENTS.md`、项目总览、当前状态和知识索引。
2. 确认本次事件目录和目标。
3. 在事件目录中处理材料。
4. 更新项目总览。
5. 更新当前状态中发生变化的部分。
6. 报告产物位置、确认项、未决事项和下一步。
