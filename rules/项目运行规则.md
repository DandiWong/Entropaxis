# 项目运行规则

> 20260818 精简：Dashboard 写入的操作细节（curl、source_ref、任务分流判据）已收敛至
> `internal-board` Skill（`.system/skills/internal-board/SKILL.md`）；本文件只保留项目组织与任务解析原则。

## 系统与项目

- `.system/` 只放通用规则、模板、初始化工具和系统专用 Skill。
- 每个项目放在系统工程之外，默认与系统工程同级。
- 不按需求、POC、Spec、交付等固定阶段预建目录。

## 工作区项目索引

> **唯一真源**：`.data/registry.md`（工作区实例数据，不分发）。
> Agent 需要项目 ID、主目录或口语关键词时，先读 `.data/registry.md`；
> 共享资料层目录（不属于 Dashboard 项目）以 [`.data/workspace-config.md`](../../.data/workspace-config.md) 为准。
> 若 `.data/registry.md` 不存在，先创建空白文件（保留表头与列定义），提示用户补填项目信息，再继续任务；不得以"未找到注册表"为由跳过项目解析。

## 时间线与交付物规范

- 有真实事件时创建 `YYYYMMDD_事件名/`。
- **文档落盘触发门禁**：并非每个问答、讨论或验证动作都要生成磁盘文件。日常技术咨询、命名建议、方案探索直接在对话中交互完成；运行测试默认只保留终端结果，不据此自动生成 HTML/Markdown 测试报告。仅当用户明确要求落档，或 Agent 询问“是否需要落入文档”并获得明确许可后，方可创建调研、方案、说明、报告/汇报等独立交付物。
- **交付物命名规范**（本节为交付物命名唯一真源，其他文件只引用不复制）：新建调研、需求、设计、方案、评审等独立交付物时（无论是否为中间产物），采用 `{{yyyymmdd}}_{{PascalCaseTopic}}.<ext>`，例如 `20260819_SystemDesign.md`、`20260819_RequirementsAssessment.md`。日期是有效事件日期；主旨使用英文 PascalCase 名词/动词短语，首字母大写，只含英文字母和数字，不使用空格、连字符或额外下划线。开发项目的 task spec 默认采用 `<ID>_<PascalCaseTopic>.md`；项目已有约定时沿用项目约定。
- **组织名称默认口径**：后续新建文件夹、文件或内容涉及组织名称时，如无明确说明，一律使用 [`.data/workspace-config.md`](../../.data/workspace-config.md) 中的默认名称口径（含禁用缩写与对外例外）；对外正式材料以收件方或官方品牌要求为准。
- **命名例外**：只有入口和工作流真源（`README.md`、`AGENTS.md`、`PRODUCT.md`、`tasks.md`、`todo.md`、`changelog.md`、`marker.md`）、机器契约以及有正式收件方命名要求的专用模板保持固定名称。测试报告不属于例外，获准生成时使用日期命名，例如 `20260821_TestReport.html`。task spec 的例外见开发通用规则。新规则默认约束新建或本轮实际修改的文件；存量批量改名须有用户明确要求。
- 材料少时直接平铺；材料明显变多后再建立 `原始材料/工作稿/定稿/`。
- 同一事件可以同时产生需求、评测、计划、培训或汇报材料。
- 不为了满足结构而创建空事件目录。

### 讨论沉淀文档结构

经充分讨论后落盘的调研、方案、问题排查、bug 修复记录等文档，按以下固定结构组织，保证日后回查可定位：

1. **主题与场景**：讨论对象是什么，锚定的具体场景/触发事件；
2. **Baseline**：讨论开始时公认的现状、口径或参照基线（含来源链接）；
3. **问题**：本次要解决的具体问题，与 baseline 的偏差；
4. **原因**：经查证的原因分析；未查明的直接写“原因未查明”，不写推测；
5. **解决方案**：已确认采用的方案及关键取舍；多方案对比时保留落选理由；
6. **遗留问题**：未决事项、待确认项、后续动作；已拍板的决策另按“决策落盘”规则同步 `_契约/当前状态.md`。

适用边界：

- 适用于：讨论后落盘的调研报告、方案设计、问题排查记录、bug 修复记录；
- 不适用于：会议纪要（专用 Skill 模板）、task spec（`开发通用规则.md`）、有固定收件方模板的对外交付物；
- 开发项目中：调研、排查、修复记录适用本结构；task spec 继续按 `开发通用规则.md` 的格式执行，两者不互斥——spec 记“怎么做”，排查记录记“为什么这么改”；
- 某要素确实不存在时写“无”并一句话说明，不整段删除，保留回查锚点。

### `docs/` 分类（开发或文档密集型项目）

普通时间线项目继续把产物放在真实事件目录，不强制增加 `docs/`。含 git 仓库或长期维护大量设计文档的项目采用以下分类：

```text
docs/
├── README.md          # 文档导航、真源层级和当前入口
├── .board.json        # 跨系统绑定（启用时）
├── 00_project/         # 任务、变更记录、计划和决策
├── 01_research/        # 调研、分析、论证和受控研究材料
├── 02_product/         # 产品目标、需求、路线和介绍材料
├── 03_design/          # UI/UX、交互和领域方案
│   └── mockups/       # 界面与交互原型
├── 04_architecture/    # 架构、接口、数据模型、部署
│   └── specs/         # task ID 绑定的实施规格
├── 05_reports/         # 评审、审计、差距评估和测试报告
└── 06_archive/         # 已被替代且已标明当前真源的历史材料
```

- `PRODUCT.md`（存在时）定义最高层产品边界；`docs/README.md` 只导航，不复制正文。
- 权威顺序通常为：产品定义 → 产品文档 → 方案设计 → 专项架构 → task spec → 项目状态与证据。
- 同一内容只有一个真源，其他文档使用链接；不保留旧路径副本。
- 目录使用 `编号_名称` 固定阅读顺序；`docs/README.md` 与 `.board.json` 留根。
- `06_archive/` 只放已有替代真源的材料，并记录替代路径。
- 普通项目不预建空分类目录；明确使用文档布局时，可通过 `init_project.py --docs-layout` 一次创建。

## 项目总览

`_项目总览.md` 只承担导航：

- 项目身份、用途、目标和相关人员；
- 按日期排列的事件索引；
- 当前有效状态入口；
- 最新产物和下一关键事件。

事件完成后追加或更新一行，不在总览中复制详细正文。

## 当前状态

`_契约/当前状态.md` 是项目唯一的当前事实：

- 只写已经确认或当前明确采用的内容；
- 每项基线链接到时间线中的证据或产物；
- 新结论覆盖旧结论时更新当前状态，旧版本仍留在原事件目录；
- 未确认内容放在"待确认"，不冒充当前事实。

### 决策落盘（跨会话记忆）

`当前状态.md` 同时是**跨会话、跨 agent 的持久记忆层**——没有落盘的决策等于没有记住，
下一次会话或换一个 agent 就会丢失。因此：

- 每当在对话或事件中**确认**一个决策、结论、基线或口径（不是临时讨论、不是待确认项），
  就把它写入所属项目的 `_契约/当前状态.md`，并链接到时间线中的证据或产物。
- 触发点：用户明确表态"就这么定 / 确认 / 采用 X"、评审形成结论、机制或口径敲定、
  选型拍板等。纯讨论、假设、候选方案不落盘（放"待确认"或留在事件记录里）。
- 与 Dashboard 的边界：Dashboard 记**任务/状态/截止/相关人**，`当前状态.md` 记
  **当前以什么为准**（事实/决策/基线/口径），两者不重复。
- 存量项目目录尚无 `_契约/当前状态.md` 时，**首次出现确认决策**才创建它（用模板），
  不为占位预建空文件。
- 覆盖旧决策时更新 `当前状态.md`，旧版本仍留在原事件目录，保留可追溯的演进。

不使用 `node`、`handoff_to`、`fields_origin` 或统一状态机。只有法规、验收或正式审批确有要求时，才增加独立契约文件。

## Agent 工作闭环

1. 读根 `AGENTS.md` 常驻层，按任务路由表按需读取规则与项目导航文档。
2. 把用户自然语言解析为任务卡，并用项目文件、Dashboard、日历和素材查证。
3. 确认本次事件目录和目标。
4. 在事件目录中处理材料。
5. 更新项目总览和当前状态中发生变化的部分；确认决策落盘。
6. 需要登记任务时按 `internal-board` Skill §6 同步 Dashboard，并重新读取验证。
7. 报告产物位置、确认项、未决事项、下一步和 Dashboard 同步结果。

自然语言任务解析（任务卡元素、查证顺序、追问边界与示例）见 [`工作区指令.md`](工作区指令.md)。

## 与 Dashboard 的边界

- 项目目录保存材料、产物、时间线、结论、基线和知识。
- Dashboard 保存执行任务、状态、截止日期、相关人及通知状态。
- `当前状态.md` 的"下一步"只记录高层方向或关键事件，不复制 Dashboard 的详细任务清单。
- Agent 看板读写统一经 `internal-board` Skill（`dash.py` + Bearer Token）；不手写 HTTP 请求，不走本地端口或公开 Tunnel。
- 新任务必须带稳定 `source_ref`（格式与幂等行为见 `internal-board` Skill §6.1）。
- 对话中的结论、知识或材料不自动转成任务；只有明确行动项才进入 Dashboard。
- 安排会议只有在用户明确要求时才写入日历。
