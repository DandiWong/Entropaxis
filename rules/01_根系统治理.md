# 根系统治理

**适用边界**：仅用于 `.entropaxis/` 根系统（控制面、规则库、工具、模板、Skill）自身的治理与自迭代。严禁把本规则（含自动提交）套用到业务项目、应用代码仓库或交付物；它们遵循自身 `AGENTS.md` 与领域规则。

设计新规则、工具、Skill、模板或数据结构时，另读 [`系统演进准则.md`](系统演进准则.md)；只修正文字、链接、数字或已有缺陷时不必。物理布局与 `data/` 写入语义见 [`控制面布局.md`](控制面布局.md)。

## 先确认归属

- 工作区元规则、安全边界、总路由：根 `AGENTS.md`（物理源 `.entropaxis/entrypoints/`）
- 跨项目通用架构与行为约束：`.entropaxis/rules/`
- 工作区实例数据、环境映射与系统自身演进/调研产物：`.entropaxis/data/`（如 `data/docs/`）
- 项目差异、项目命令、项目硬约束：最近的项目 `AGENTS.md`
- 设计决策与验收条件：对应 Spec
- 当前实现事实与私有配置：代码、配置与可验证运行状态
- 第三方或上游包约束：其仓库或子目录自带的 `AGENTS.md`

同一事实只保留一个正文；其他文件使用链接和一句用途说明。

## 自迭代闭环

修改 `.entropaxis/` 下任何规则、模板、工具或 Skill 时，在当轮交互内完整执行以下五步，不得跳步交付：

1. **归属判别与最小修改**：按上述归属确定唯一真源，做 Token 经济性评估，只改能消除问题的最小范围。
2. **真源同步与联动校验**：
   - **根入口联动**：规则增删改名时同步 `.entropaxis/entrypoints/AGENTS.md` 的路由与安全边界，随后执行 `python3 .entropaxis/tools/bootstrap.py` 同步到根目录。
   - **数据与研究产物联动**：新增实例参数须在 `.entropaxis/data/` 声明；本次调研、推演产物归档至 `.entropaxis/data/docs/`，不得散落根目录。
   - **声明外置悬空核验（防隐式假设铁律）**：规则正文新增或引用 `.entropaxis/data/` 下的实例声明字段时，核验该字段在初始化或分发到新环境时是否可能缺失；有此风险时，必须在同一处规则正文中显式给出兜底降级方案。
   - **写入者必须真实存在（防空壳真源）**：正文声明某文件"由 X 生成/维护"时，核验 X 真的会写它；需要沉淀为机制时比照 `文件交付.md` 4.3 节（模板 + 自动检测 + 人类仲裁 + 优雅降级）。
3. **双重体检门禁**：以下两条命令必须全部通过，阻断项清零、建议项逐条给出处置结论：
   ```bash
   python3 -m unittest discover -s .entropaxis/tests -t .entropaxis
   python3 .entropaxis/tools/lint_workspace.py
   ```
4. **交付验证**：在回复中按《软件工程》「检查按影响选」输出 `检查对象`、`证据`、`结论`（通过/阻断/未验证）、`未覆盖范围`，不产出数字评分。
5. **Git 交付（仅限 `.entropaxis/` 本身）**：精确 `git add <file>` 暂存本次改动；验证通过且无阻断时自动 `git commit`；不自动 `git push`。暂存区外已有他人未提交改动时不得顺带提交。严禁对业务项目仓库自动提交或推送。

## 入口约束

- 根入口只保留元规则、安全边界、工具指引和总路由（行数预算 ≤50 行）。
- 项目入口应当薄：工作区链接、按需入口、项目硬约束和项目验证命令（行数预算 ≤60 行）。
- 不复制系统规则，不内嵌完整 README、目录树、部署手册或会漂移的测试数量。
- `AGENTS.md` 内不写 `@` 导入；`CLAUDE.md` 只允许一行 `@AGENTS.md`。
- 受工具管理的区块原样保留，在区块外添加本地补充；不为统一风格改写上游包级规则。

## 规则审计流程

1. 盘点作用域内的规则、入口、引用关系和 Git 状态。
2. 标记重复、冲突、失效链接、自引用、过时数字、项目专属要求，以及新初始化/分发场景下悬空的 `.entropaxis/data/` 实例声明引用。
3. **退役候选识别**：命中任一条件即登记为退役候选：① 防范的失效模式已由工具机械承担；② 引用的真源、机制或外部形态已不存在；③ 本轮作用域内零命中且无可预见触发场景。判据以本轮现场核对为准。**只产出候选清单与理由，由人仲裁后执行，严禁自动删除。**
   - **超预算即触发**：改动导致规则文件超出 `lint_workspace.py` 第 17 项行数预算时，同轮必须提出等量退役候选。
4. **全域路由完整性核验**：核查根入口路由、项目注册表 (`.entropaxis/data/templates/registry.md`)、各业务项目入口 `AGENTS.md`（单锚点根回链与零废弃规则名）以及事务胶囊容器链条，确保无悬空。
5. 区分一方文件、受管理区块、第三方/上游规则和用户未完成改动。
6. 选择唯一真源，做能消除问题的最小改动；最后复核链接、层级、行数、术语和差异。

## 完成标准

- 每条规则能指出唯一真源和适用范围。
- 最近的入口可把执行者路由到所需材料，且不要求预读整库。
- 无对用户改动的无意覆盖。
- 单元测试与 `lint_workspace.py` 阻断项全部清零，建议项逐条给出处置结论。
