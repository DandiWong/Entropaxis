# 根系统治理

> **唯一适用边界（铁律）**：本规则**仅且严格用于 `.entropaxis/` 根系统（Entropaxis 控制面、规则库、脚手架工具与模板）自身的治理与自迭代**。严禁将本规则（包括自迭代交付验证、自动提交等机制）泛化或套用到任何业务项目、应用代码仓库或交付物中。各业务项目严格遵循自身的 `AGENTS.md` 与对应领域规则。

## 先确认归属

| 内容 | 唯一归属 |
|---|---|
| 工作区元规则、安全边界、总路由 | 根 `AGENTS.md`（物理源位于 `.entropaxis/entrypoints/`） |
| 跨项目通用架构与行为约束 | `.entropaxis/rules/` |
| 工作区实例数据、环境映射与系统自身演进/调研产物 | `.entropaxis/data/`（如 `.entropaxis/data/docs/`） |
| 项目差异、项目命令、项目硬约束 | 最近的项目 `AGENTS.md` |
| 设计决策与验收条件 | 对应 Spec |
| 当前实现事实与私有配置 | 代码、配置与可验证运行状态（代码库应用自身管理机制） |
| 第三方或上游包约束 | 其仓库或子目录自带的 `AGENTS.md` |

同一事实只保留一个正文；其他文件使用链接和一句用途说明。

`.entropaxis/` 与 `.entropaxis/data/` 的物理布局、写入语义与来源映射见 [`控制面布局.md`](控制面布局.md)。

## 根系统演进准则（系统演进五性准则）

对 `.entropaxis/`（规则、Skill、模板、工具）的演进与修改，必须满足以下五项硬约束：

1. **改动前置门禁**：对系统工程的任何改动，必须先以 `00_元规则.md` 作为判断基准。
2. **系统演进五性准则**：
   - **完备性 (Completeness)**：全生命周期闭环，覆盖从原始素材、产品设计、工程实现、运营交付到价值回收各阶段，无断点或悬空逻辑；
   - **通用性 (Generality)**：沉淀中立抽象机制而非特定平台打补丁，零业务系统名/品牌/绝对路径硬编码，跨业务场景通用普适；
   - **安全性 (Security)**：操作严格遵循授权边界，物理数据/机密凭据严格隔离，脚手架防覆盖防污染；
   - **健壮性 (Robustness)**：异常降级、幂等重入与自愈机制，测试与体检全绿；
   - **Token 经济性 (Token Efficiency & ROI)**：系统演进遵循 [`00_元规则.md`](00_元规则.md) 第 3 条；重构与新造能力必须杜绝排版语法税，优先由纯标准库本地脚本承载计算并返回高密度结果（可调用 `token-optimizer` 技能辅助审查）；
   - **降级分两类**：软降级（外部 Provider 缺失不阻断流程，如看板 CLI、文件打开程序）必须留痕；硬降级禁止（审计独立性等本质契约）必须由独立进程承担，缺失即阻断，不得静默降级。**显式人工豁免路径**：审计独立性缺失时允许用户对单条 Critical 问题记录 `waived_by_user`（绑定问题 ID、当前受审指纹、确认事件与适用范围），使实施可继续推进；该终态不等同于独立复核通过，不得记为 Reviewer `closed`，外置环境恢复后仍应补一次外置复核。字段契约与三态定义见 [`角色协作.md`](角色协作.md)「方案审修协同闭环」。
3. **声明与逻辑解耦（零系统绑定铁律）**：
   - **逻辑中立**：`.entropaxis/` 内部（规则、工具、模板、通用 Skill）只维护纯抽象状态机、生命周期与调度逻辑，严禁硬编码任何具体业务系统名（如特定外部看板/平台/空间）；
   - **声明外置**：所有外部系统映射、实例参数、环境事实与机密凭据，一律在 `.entropaxis/data/`（如 `.entropaxis/data/templates/registry.md`、`.entropaxis/data/credentials/`）或项目局部配置（`docs/.board.json`）中以 Key-Value 声明；
   - **契约消费**：`.entropaxis/` 仅通过抽象契约动态读取外部参数并支持自适应降级，实现系统逻辑与外部环境的彻底解耦。
   - **能力三分与执行体归属**：抽象契约归 `.entropaxis/rules/`，实例声明归 `.entropaxis/data/`，**执行体归 Skill**。判据看「随不随本体分发」——执行体不随分发的机制，其触发词、指令语义与规则正文必须一并内化进该 Skill，`.entropaxis/` 一行不留；留下的会成为收件方读到的死指令（有路由、无执行体）。
   - **依赖单向**：Skill 可引用控制面，控制面不得反向依赖 Skill，Skill 亦不得把控制面设为运行前置（独立安装即失效）。工作区级能力按「存在即用、缺失即降级」的可选增强接入，既不硬依赖也不另建第二份实现；细则见 [`技能设计.md`](技能设计.md) 6.2。
   - **默认值不得由系统猜定**：模板渲染、初始化与自愈为实例参数填默认值时，只允许留空占位或用户可见的待填标记。既不得写死任何具体工作区形态（目录名、组织名、路径布局）——那等于把某一个工作区的长相分发给所有收件方；也不得拿自动探测结果冒充默认值或据此追加确认——探测出的是候选，不是事实。
4. **双保险与内生契约（防单层穿透）**：关键执行门禁（如文件落盘打开、质量自检）必须在“根入口宏观动作矩阵”与“垂直 Skill 尾部 SOP”两端双向固化，防止模型在复杂任务中因局部认知窄化而漏执行全局动作。
5. **正交收敛与单一真源（防碎片孤岛）**：跨项目规则必须按正交切面高度收敛（如项目存储、开发工程、文件交付、表达发布），同一事实只保留一个物理真源正文，严禁跨文件复制黏贴或过度碎片化。
   - **领域规则只做编排（防 SOP 膨胀）**：领域回答「做什么」，机制回答「怎么做」。领域规则正文只声明三项——**收集什么输入、产出什么交付物、依次调用哪些通用机制**；收集、判断、生成、落盘、审计等通用环节一律引用既有规则正文，严禁在领域规则内重写一套。判据：同族领域切换（如同一资产族下换一种申报类型）应只改前两项，若被迫改动第三项所指向的机制描述，即为编排失败，须把该机制上收为通用规则。
   - **规则文本瘦身**：单文件行数预算、复述改引用、判据与操作手册分离及六条不许瘦红线，见 [`表达文风.md`](表达文风.md)「规则瘦身」；门禁由 `lint_workspace.py` 第 17、18 项机械检出。
6. **示例脱敏与去实体化（零真实实体铁律）**：
   - **严禁真实敏感实体**：`.entropaxis/` 内部所有规则、文档、模板、测试用例与说明示例中，**严禁出现任何与工作区利益相关的真实机构、企业、医院、受控课题、真实项目或真实个人名称**；
   - **合法必需场景豁免**：公共权威数据源调用（如专利局公开检索服务）、开源许可署名（LICENSE 版权声明，依法必须保留）、开源依赖出处与方法论致谢、公共规范引用（如 keepachangelog/semver）不属于泄漏，可原样出现；豁免项必须与工作区利益无关联，新增随包外部数据源或致谢时人工复核一次；
   - **规范占位与泛化代称**：凡涉及示例、占位符或模板演示，一律使用泛化代称（如 `某医院&某公司_某课题调研方案`、`某甲方&某乙方_某系统设计方案`、`某企业_智能质检方案`）或抽象变量 `{{甲方}}&{{乙方}}_{{主题}}`，杜绝任何商业机密、敏感医疗研究或组织实体信息的泄漏风险。
7. **子入口单锚点总线铁律 (Single-Anchor Inheritance)**：
   - **禁止子项目硬编码具体规则**：全工作区所有业务项目与工程应用子目录的 `AGENTS.md`，**严禁直接引用 `.entropaxis/rules/` 下的具体规则物理文件名**；
   - **唯一合法形式**：【工作区上下文】必须且只能声明指向工作区根入口的相对路径 `{{ROOT_AGENTS_PATH}}`（如 `../AGENTS.md` 或 `../../../AGENTS.md`）；
   - **根入口总线分发**：根 `AGENTS.md` 作为唯一的按需路由总线，任何底层规则调整只需维护根入口一处，全工作区所有子项目自动全量继承，彻底杜绝网状断链。
8. **门禁自身四律（防检查器盲区）**：治理门禁也是控制面的一部分，同受上述准则约束。以下四条专门针对"检查器看不见自己"的结构性盲区，命中即须整改而非记入盲区注释：
   - **同受约束（防自指豁免）**：检查器不得将自身排除在扫描范围之外。零系统绑定的禁用实体词表一律外置于 `.entropaxis/data/rules/零系统绑定词表.md`，严禁写死在 `.entropaxis/` 内换取实现便利——否则该文件将成为控制面里唯一硬编码组织实体的地方，并随版本库分发给每一位收件方。**词表格式**：每行一条 `- <禁用词>`，`（）` 内与 `#` 后为注释不参与匹配，大小写不敏感；新工作区自行按本机构真实实体逐条补齐。**词表缺失时软降级**：结构性端点检查照常执行，实体词检查停用并在体检输出留痕告警，不静默通过。
   - **多状态求值（防单点绿灯）**：门禁必须在其声称覆盖的**每一个环境状态**上求值，而非只在开发者本机。至少覆盖「已初始化本机」与「新克隆收件方」两个求值点——同一份代码在两个状态下可能给出两个不同的真相；后者由 `check_distribution.py` 承担并纳入系统自检。
   - **执行态可见（防静态盲信）**：涉及工具运行时行为的契约，必须实际执行并核验其输出，不得以语法编译或静态读码替代。越界读取、自相矛盾告警等运行期缺陷在静态检查下完全不可见。
   - **空态即初始态（防开箱即红）**：门禁必须区分「契约破损」与「尚未开始使用」。收件方接入前工作区就有自己的目录、注册表尚未登记任何项目、`.entropaxis/data/` 声明尚未落地——均为合法初始态，一律降为建议项并给出下一步动作，待用户进入该机制后再转为阻断。**判据**：若某阻断项的修复动作是"你本来就还没开始用这个系统"，它就不是缺陷。求值环境同样不得为空——只在空壳树上跑的门禁，求值不到任何与既有内容相关的状态。
## 规则审计流程

1. 盘点作用域内的规则、入口、引用关系和 Git 状态。
2. 标记重复、冲突、失效链接、自引用、过时数字、项目专属要求，以及新初始化/分发场景下悬空的 `.entropaxis/data/` 实例声明引用。
3. **退役候选识别（防规则只增不减）**：规则库天然以加法演进，每轮审计必须同时做减法。命中任一条件即登记为退役候选：① 其防范的失效模式已由工具机械承担，正文中的手工核对步骤成为冗余；② 所引用的真源、机制或外部形态已不存在；③ 本轮审计作用域内零命中，且无可预见的未来触发场景。判据一律以本轮现场核对为准，不依赖长期命中账本。**退役只产出候选清单与理由，由人仲裁后执行合并或删除，严禁自动删除。**
   - **超预算即触发**：本次改动导致任一规则文件超出 `lint_workspace.py` 第 17 项行数预算时，同轮必须提出等量退役候选，否则不予交付——加法与减法在同一次交互内闭合。
4. **全域路由完整性核验**：递归核查根入口动作矩阵、项目注册表 (`.entropaxis/data/templates/registry.md`)、全工作区各业务项目入口 `AGENTS.md`（单锚点根回链与零废弃规则名检测）以及事务胶囊容器链条，确保 100% 连通闭合无悬空。
5. 区分一方文件、受管理区块、第三方/上游规则和用户未完成改动。
6. 选择唯一真源，做能消除问题的最小改动。
7. 检查链接、层级、行数、术语和项目验证命令；最后复核差异。
## 规则系统自迭代闭环 (SOP)

修改系统工程（`.entropaxis/` 下任何规则、模板、工具或 Skill）时，**必须在当轮交互中严格完整执行五步自迭代闭环，严禁跳步交付**：

1. **归属判别与 Token 经济性评估**：按元规则确定内容唯一归属（根入口 / 规则 / 模板 / 工具 / Skill），并对改动执行 Token 经济性评估与最小修改，杜绝高语法税格式与冗余长文本。
2. **真源同步与联动校验（铁律）**：对 `.entropaxis/` 改动时，**必须显性核验并联动改动其下嵌套的 `data/` 与根入口 `AGENTS.md`**：
   - **根入口联动 (`AGENTS.md`)**：核验规则增删改是否需同步更新 `.entropaxis/entrypoints/AGENTS.md` 的动作路由矩阵、安全边界或工具指引，随后执行 `python3 .entropaxis/tools/bootstrap.py` 物理同步覆盖根入口（杜绝云盘软链 Conflict 冲突）；
   - **数据与研究产物联动 (`.entropaxis/data/`)**：核查是否有新增实例参数需同步在 `.entropaxis/data/` 声明，且因本次系统调研、推演、改动产生的文件必须规范归档于 `.entropaxis/data/docs/` 等合理子目录下，严禁散落根目录；
   - **声明外置悬空核验（防隐式假设铁律）**：规则正文新增或引用任何 `.entropaxis/data/` 下的实例声明字段时，必须核验该字段在系统初始化或分发至新环境时是否可能缺失或失效（无模板预置、无自动检测/仲裁机制生成该值）；存在此风险时，必须在同一处规则正文中显式给出兜底降级方案（缺失或不可执行时的默认行为），不得遗留隐式假设。
   - **写入者必须真实存在（防空壳真源）**：规则或模板正文声明某文件"由 X 生成/维护"时，必须核验 X 真的会写它。声明了写入者却无人落笔，该真源在新环境永远是空壳，依赖它的下游全部静默失效——比压根不声明更危险，因为读者会以为它已经被管起来了。确有必要沉淀为可复用机制时，比照 `文件交付.md` 4.3–4.4 节的模板 + 自动检测 + 人类仲裁 + 优雅降级范式落地；
3. **双重体检门禁**：必须执行并通过单元测试与工作区体检双重门禁：
   ```bash
   python3 -m unittest discover -s .entropaxis/tests -t .entropaxis
   python3 .entropaxis/tools/lint_workspace.py
   ```
   确保阻断项与治理建议项全部绿灯。
4. **交付验证（必显交付物 · 检查对象/证据/结论/未覆盖范围）**：完成每次系统自迭代时，**必须在回复输出中呈现验证结果**，按改动影响选择验证深度（判据见 [`软件工程.md`](软件工程.md)「检查按影响选」）；结论只取**通过 / 阻断 / 未验证**三态，不产出缺乏校准依据的数字评分。五个审阅维度（完备性、通用性、安全性、健壮性、可移植性）作为需要时的审阅提示，唯一真源见 [`软件工程.md`](软件工程.md)。
   - **输出格式**：`检查对象`、`证据`（引用具体检查项或 grep 命中数）、`结论`（通过/阻断/未验证）、`未覆盖范围`。

- 根入口只保留元规则、安全边界、工具指引和总路由（行数预算 $\le 50$ 行）。
- 项目入口应当薄：工作区链接、按需入口、项目硬约束和项目验证命令（行数预算 $\le 60$ 行）。
- 不复制系统规则，不内嵌完整 README、目录树、部署手册或会漂移的测试数量。
- 不使用 `@AGENTS.md` 等自引用。
- 受工具管理的区块原样保留，在区块外添加本地补充。
- 不为了统一风格改写上游包级规则；只有明确任务要求时才修改。

## 完成标准

- 每条规则能指出唯一真源和适用范围。
- 最近的入口可把执行者路由到所需材料，且不要求预读整库。
- 无对用户改动的无意覆盖（失效引用与自引用已由体检机械检出）。
- `lint_workspace.py` 全部体检项与单元测试 100% 绿灯通过（阻断项必须清零，治理建议项须逐条给出处置结论）。
