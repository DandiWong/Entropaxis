# 根系统治理

> **唯一适用边界（铁律）**：本规则**仅且严格用于 `.system/` 根系统（Entropaxis 控制面、规则库、脚手架工具与模板）自身的治理与自迭代**。严禁将本规则（包括自迭代五维评估、自动提交推送等机制）泛化或套用到任何业务项目、应用代码仓库或交付物中。各业务项目严格遵循自身的 `AGENTS.md` 与对应领域规则。

## 先确认归属

| 内容 | 唯一归属 |
|---|---|
| 工作区元规则、安全边界、总路由 | 根 `AGENTS.md`（物理源位于 `.system/root-configs/`） |
| 跨项目通用架构与行为约束 | `.system/rules/` |
| 工作区实例数据、环境映射与系统自身演进/调研产物 | `.data/`（如 `.data/docs/`） |
| 项目差异、项目命令、项目硬约束 | 最近的项目 `AGENTS.md` |
| 设计决策与验收条件 | 对应 Spec |
| 当前实现事实与私有配置 | 代码、配置与可验证运行状态（代码库应用自身管理机制） |
| 第三方或上游包约束 | 其仓库或子目录自带的 `AGENTS.md` |

同一事实只保留一个正文；其他文件使用链接和一句用途说明。

## 根系统演进准则（系统演进五性准则）

对 `.system/`（规则、Skill、模板、工具）的演进与修改，必须满足以下五项硬约束：

1. **改动前置门禁**：对系统工程的任何改动，必须先以 `00_元规则.md` 作为判断基准。
2. **系统演进五性准则**：
   - **完备性 (Completeness)**：全生命周期闭环，覆盖从原始素材、产品设计、工程实现、运营交付到价值回收各阶段，无断点或悬空逻辑；
   - **通用性 (Generality)**：沉淀中立抽象机制而非特定平台打补丁，零业务系统名/品牌/绝对路径硬编码，跨业务场景通用普适；
   - **安全性 (Security)**：操作严格遵循授权边界，物理数据/机密凭据严格隔离，脚手架防覆盖防污染；
   - **健壮性 (Robustness)**：异常与依赖缺失时支持优雅降级、幂等重入与自愈机制，测试与体检全绿；
   - **可移植性 (Portability)**：坚持 Local-First 纯标准库自闭环设计，外部服务均以 Provider 契约可插拔挂载，确保 `.system/` 可随时作为通用底座直接分发至任意独立仓库。
3. **声明与逻辑解耦（零系统绑定铁律）**：
   - **逻辑中立**：`.system/` 内部（规则、工具、模板、通用 Skill）只维护纯抽象状态机、生命周期与调度逻辑，严禁硬编码任何具体业务系统名（如特定外部看板/平台/空间）；
   - **声明外置**：所有外部系统映射、实例参数、环境事实与机密凭据，一律在 `.data/`（如 `.data/registry.md`、`.data/credentials/`）或项目局部配置（`docs/.board.json`）中以 Key-Value 声明；
   - **契约消费**：`.system/` 仅通过抽象契约动态读取外部参数并支持自适应降级，实现系统逻辑与外部环境的彻底解耦。
4. **双保险与内生契约（防单层穿透）**：关键执行门禁（如文件落盘打开、质量自检）必须在“根入口宏观动作矩阵”与“垂直 Skill 尾部 SOP”两端双向固化，防止模型在复杂任务中因局部认知窄化而漏执行全局动作。
5. **正交收敛与单一真源（防碎片孤岛）**：跨项目规则必须按正交切面高度收敛（如项目存储、开发工程、文件交付、表达发布），同一事实只保留一个物理真源正文，严禁跨文件复制黏贴或过度碎片化。
6. **示例脱敏与去实体化（零真实实体铁律）**：
   - **严禁真实敏感实体**：`.system/` 内部所有规则、文档、模板、测试用例与说明示例中，**严禁出现任何真实机构、企业、医院、受控课题、真实项目或真实个人名称**；
   - **规范占位与泛化代称**：凡涉及示例、占位符或模板演示，一律使用泛化代称（如 `某医院&某公司_某课题调研方案`、`某甲方&某乙方_某系统设计方案`、`某企业_智能质检方案`）或抽象变量 `{{甲方}}&{{乙方}}_{{主题}}`，杜绝任何商业机密、敏感医疗研究或组织实体信息的泄漏风险。
## 规则审计流程

1. 盘点作用域内的规则、入口、引用关系和 Git 状态。
2. 标记重复、冲突、失效链接、自引用、过时数字和项目专属要求。
3. 区分一方文件、受管理区块、第三方/上游规则和用户未完成改动。
4. 选择唯一真源，做能消除问题的最小改动。
5. 检查链接、层级、行数、术语和项目验证命令；最后复核差异。

## 规则系统自迭代闭环 (SOP)

修改系统工程（`.system/` 下任何规则、模板、工具或 Skill）时，**必须在当轮交互中严格完整执行五步自迭代闭环，严禁跳步交付**：

1. **归属判别与最小修改**：按元规则确定内容唯一归属（根入口 / 规则 / 模板 / 工具 / Skill），做能消除问题的最小改动。
2. **真源同步与同级联动校验（铁律）**：对 `.system` 改动时，**必须显性核验并联动改动同级的 `.data/` 与根入口 `AGENTS.md`**：
   - **根入口联动 (`AGENTS.md`)**：核验规则增删改是否需同步更新 `.system/root-configs/AGENTS.md` 的动作路由矩阵、安全边界或工具指引，随后执行 `python3 .system/tools/bootstrap.py` 物理同步覆盖根入口（杜绝云盘软链 Conflict 冲突）；
   - **数据与研究产物联动 (`.data/`)**：核查是否有新增实例参数需同步在 `.data/` 声明，且因本次系统调研、推演、改动产生的文件必须规范归档于 `.data/docs/` 等合理子目录下，严禁散落根目录；
   - **模板契约闭环**：检查所有模板与脚手架中的变量声明与闭合状态。
3. **双重体检门禁**：必须执行并通过单元测试与工作区体检双重门禁：
   ```bash
   python3 -m unittest discover -s .system/tests
   python3 .system/tools/lint_workspace.py
   ```
   确保阻断项与治理建议项全部绿灯。
4. **五维架构评估（必显交付物 · 单项 100 分独立门禁制）**：完成每次系统自迭代时，**必须在回复输出中呈现精炼的五维评估表（仅展示 `评估维度`、`实测得分`、`门禁结论`、`量化评估依据` 4 列，不再展示满分/及格线/门禁冗余列）**。5 个维度均独立采用 100 分制量化评分，不计算加权总分。各维度实测得分的具体计算规则（客观锚点、扣分项、一票否决条款）见 [`五维评估.md`](五维评估.md)，本条只保留门禁线定义。**准予交付铁律：必须 5 项指标全部同时达到或超过门禁线（5 维全绿），任意 1 项不达标即直接阻断交付并强制整改**：
   | 维度 | 满分 | 及格线 | 阻断门禁 | 考核要点 |
   |---|---|---|---|---|
   | 完备性 (Completeness) | 100 | 85 | < 85 | 全生命周期闭环，无断点、悬空逻辑或未闭合契约 |
   | 通用性 (Generality) | 100 | 85 | < 85 | 中立抽象机制，严禁硬编码具体业务系统名/品牌/绝对路径 |
   | 安全性 (Security) | 100 | 90 | < 90 | 授权边界、数据与凭据物理隔离，越权或污染一票否决 |
   | 健壮性 (Robustness) | 100 | 85 | < 85 | 异常降级、幂等重入与自愈；单元测试与体检必须 100% 绿灯（任一失败直接判 0 分阻断）|
   | 可移植性 (Portability) | 100 | 85 | < 85 | Local-First 纯标准库自闭环设计与 Provider 契约可插拔性，确保随根系统自由分发 |

   - **输出表格标准格式**：`| 评估维度 | 实测得分 | 门禁结论 | 量化评估依据 |`

- 根入口只保留元规则、安全边界、工具指引和总路由（行数预算 $\le 50$ 行）。
- 项目入口应当薄：工作区链接、按需入口、项目硬约束和项目验证命令（行数预算 $\le 60$ 行）。
- 不复制系统规则，不内嵌完整 README、目录树、部署手册或会漂移的测试数量。
- 不使用 `@AGENTS.md` 等自引用。
- 受工具管理的区块原样保留，在区块外添加本地补充。
- 不为了统一风格改写上游包级规则；只有明确任务要求时才修改。

## 完成标准

- 每条规则能指出唯一真源和适用范围。
- 最近的入口可把执行者路由到所需材料，且不要求预读整库。
- 无新增失效引用、自引用或对用户改动的无意覆盖。
- 14 项工作区健康体检与单元测试 100% 绿灯通过。
