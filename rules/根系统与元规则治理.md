# 根系统与元规则治理

本规则用于约束工作区控制面（根 `AGENTS.md` / `CLAUDE.md`）、系统工程（`.system/`）、跨项目规则与各级 `AGENTS.md` 的治理与演进。目标是维持单一真源、消除冗余与歧义、严控上下文窗口。

## 先确认归属

| 内容 | 唯一归属 |
|---|---|
| 工作区元规则、安全边界、总路由 | 根 `AGENTS.md`（物理源位于 `.system/root-configs/`） |
| 跨项目通用架构与行为约束 | `.system/rules/` |
| 工作区实例数据与环境映射 | `.data/` |
| 项目差异、项目命令、项目硬约束 | 最近的项目 `AGENTS.md` |
| 设计决策与验收条件 | 对应 Spec |
| 当前实现事实与私有配置 | 代码、配置与可验证运行状态（代码库应用自身管理机制） |
| 第三方或上游包约束 | 其仓库或子目录自带的 `AGENTS.md` |

同一事实只保留一个正文；其他文件使用链接和一句用途说明。

## 规则审计流程

1. 盘点作用域内的规则、入口、引用关系和 Git 状态。
2. 标记重复、冲突、失效链接、自引用、过时数字和项目专属要求。
3. 区分一方文件、受管理区块、第三方/上游规则和用户未完成改动。
4. 选择唯一真源，做能消除问题的最小改动。
5. 检查链接、层级、行数、术语和项目验证命令；最后复核差异。

## 规则系统自迭代闭环 (SOP)

修改系统工程（`.system/`）或跨项目通用规则时，必须严格执行四步自迭代闭环：

1. **归属判别**：按元规则确定内容唯一归属（根入口 / 规则 / 模板 / 工具 / Skill），做能消除问题的最小改动。
2. **真源同步**：修改 `root-configs/AGENTS.md` 时同步工作区根 `AGENTS.md`；模板修改时检查所有变量声明与闭合。
3. **双重体检**：必须通过单元测试（`python3 -m unittest discover -s tests`）与工作区体检（`python3 .system/tools/lint_workspace.py`），阻断项与治理建议项全部绿灯。
4. **受控交付**：精确暂存变更文件，严禁盲目暂存；经用户明确授权后，提交并推送远程。

## AGENTS.md 约束

- 根入口只保留元规则、安全边界、工具指引和总路由（行数预算 $\le 50$ 行）。
- 项目入口应当薄：工作区链接、按需入口、项目硬约束和项目验证命令（行数预算 $\le 60$ 行）。
- 不复制系统规则，不内嵌完整 README、目录树、部署手册或会漂移的测试数量。
- 不使用 `@AGENTS.md` 等自引用。
- 受工具管理的区块原样保留，在区块外添加本地补充。
- 不为了统一风格改写上游包级规则；只有明确任务要求时才修改。

## 完成标准

- 每条规则能指出唯一真源和适用范围。
- 最近的入口可把执行者路由到所需材料，且不要求预读整库。
- 无新增失效引用、自引用或对用户改动的无意覆盖。
- 14 项工作区健康体检与单元测试 100% 绿灯通过。
