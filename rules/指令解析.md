# 指令解析

收到任意自然语言指令时，将其解析为任务卡并查证关键元素。本文件只管解析方法，不含任何具体机制的执行语义：

| 指令类型 | 真源 |
|---|---|
| 日常业务动作（同步、任务、记录/沉淀、复盘、定位查找、初始化、Tip）| [`工作流指令.md`](工作流指令.md) |
| 系统治理动作（审计、修正、系统自检、新迭代、机制转工具、分发/注册 Skill）| [`治理指令.md`](治理指令.md) |

普通问答或提到表中词汇不自动触发写入；所有外部写入受根 `AGENTS.md` 安全边界约束。精确命令以对应工具和专项规则为准，本文件不复制 CLI 参数。

## 通用任务解析

收到任意自然语言指令时，先在内部形成任务卡，不要求用户按表单重述：

| 元素 | 含义 |
|---|---|
| 时间 | 事件时间、执行时间和截止日期，三者分别识别 |
| 项目 | 项目名称、简称、项目 ID 和工作目录 |
| 动作 | 整理、撰写、评审、修改、汇报、发送等 |
| 对象 | 会议纪要、需求、合同、报告、课件等 |
| 素材 | 附件、链接、录音、转写、笔记、历史文件和知识依据 |
| 产出 | 内容目标、格式、受众、保存位置和完成标准 |
| 执行信息 | 负责人、相关人、截止日期、敏感性和是否需要通知 |

### 解析与查证顺序

1. 优先采用用户本句中的明确表达，其次采用本轮附件和链接，再采用当前对话上下文。
2. 项目按“精确名称或 ID → 已登记简称 → 当前项目 → 上下文”形成候选；项目索引与查证方式统一见 [`项目组织.md`](项目组织.md)。多个候选仍无法唯一确定时标记为歧义。
3. “今天、明天、下周五”等相对时间以当前会话日期和时区换算为绝对日期。时间修饰会议、材料或事件名时记为事件时间；修饰“完成、提交、交付”时记为截止日期。
4. 素材只记录用户明确提供或上下文可验证的线索，不在解析层规定检索顺序；由具体工作流依据项目和对象查找。
5. 格式、保存位置、工具与执行机制只记录用户的明确要求；未指定项留给对应工作流和专项规则决定。
6. 涉及发送、发布、删除、覆盖、个人或医疗数据时，在任务卡中标记授权或敏感性要求；实际门禁遵循根 `AGENTS.md`。

### 追问边界

解析层只在下列信息无法形成唯一任务卡时提出问题：

- 项目存在多个有效候选；
- 必需素材缺失或候选素材互相冲突；
- 受众或格式会显著改变产出且无法判断；
- 用户明确要求的动作需要授权，但授权状态不明确；
- 用户表述与已读取的 `DECISIONS.md` 当前基线明显冲突。

其余缺省项保持未指定，由执行规则采用其保守默认值。用户已经说清且任务可直接执行时，不把任务卡复述变成确认门槛。
