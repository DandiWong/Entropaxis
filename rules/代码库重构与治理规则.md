# 规则与代码库治理

本规则用于跨文件重构、规则审计和 `AGENTS.md` 整理。目标是减少重复和歧义，同时保护项目边界与已有工作。

## 先确认归属

| 内容 | 唯一归属 |
|---|---|
| 工作区元规则、安全边界、总路由 | 根 `AGENTS.md` |
| 跨项目通用约束 | `.system/rules/` |
| 工作区实例数据与环境映射 | `.data/` |
| 项目差异、项目命令、项目硬约束 | 最近的项目 `AGENTS.md` |
| 设计决策与验收条件 | 对应 Spec |
| 当前实现事实与私有配置 | 代码、配置与可验证运行状态（代码库应用自身管理机制） |
| 第三方或上游包约束 | 其仓库或子目录自带的 `AGENTS.md` |
同一事实只保留一个正文；其他文件使用链接和一句用途说明。

## 审计流程

1. 盘点作用域内的规则、入口、引用关系和 Git 状态。
2. 标记重复、冲突、失效链接、自引用、过时数字和项目专属要求。
3. 区分一方文件、受管理区块、第三方/上游规则和用户未完成改动。
4. 选择唯一真源，做能消除问题的最小改动。
5. 检查链接、层级、行数、术语和项目验证命令；最后复核差异。

## AGENTS.md 约束

- 根入口只保留元规则、安全边界和路由。
- 项目入口应当薄：工作区链接、按需入口、项目硬约束和项目验证命令。
- 不复制系统规则，不内嵌完整 README、目录树、部署手册或会漂移的测试数量。
- 不使用 `@AGENTS.md` 等自引用。
- 受工具管理的区块原样保留，在区块外添加本地补充。
- 不为了统一风格改写上游包级规则；只有明确任务要求时才修改。

## 代码库治理

- 先找共享根因和现有复用点，再决定重构范围。
- 删除无用层次优先于新增抽象；保留必要的输入校验、安全和可恢复性。
- 覆盖率、双语文档、录屏、堆叠 PR 等不是工作区通用门槛，只有项目或任务明确要求时执行。
- 特定仓库 Skill 只在匹配仓库和任务时使用，不写入全局强制流程。
- 独立代码库应用自身管理机制（内部依赖、私有配置与工程流），系统规则不强行介入其内部结构。

## 完成标准

- 每条规则能指出唯一真源和适用范围。
- 最近的入口可把执行者路由到所需材料，且不要求预读整库。
- 无新增失效引用、自引用或对用户改动的无意覆盖。
- 已运行与改动风险相称的检查，并如实记录未验证项。
