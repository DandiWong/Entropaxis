# 技能维护

本规则只定义本工作区维护 Skill 的归属和边界。创建或更新 Skill 时优先使用已提供的 `skill-creator` 指南，不在这里复制运行时格式说明。

## 归属

- 工作区 Skill 真源位于 `.system/skills/<skill-name>/`。
- 仅供本工作区使用的 Skill 可以引用根规则和系统规则。
- 需要分发到其他环境的 Skill 必须自包含，不依赖工作区私有路径或未随包发布的文件。
- 全局安装目录和其他 Agent 目录不是源文件位置；只有明确要求安装或发布时才同步。

## 内容边界

- `SKILL.md` 只保留触发条件、工作流、输入输出和安全约束。
- 详细参考、模板和脚本按需放入相邻目录，并从 `SKILL.md` 精确路由。
- 不复制项目索引、状态映射或系统规则正文；工作区 Skill 使用链接，分发型 Skill 只携带执行必需内容。
- 不把一次性任务步骤固化为 Skill，也不为单一调用增加包装层。
- **物理交付与双保险契约**：凡生成/导出 `.pptx`、`.docx`、`.xlsx`、`.pdf` 或图片等通用文件的 Skill，其工作流尾部必须显性包含调用所在系统打开文件能力（macOS `open "<file>"` / Windows `start "" "<file>"` / Linux `xdg-open "<file>"`）使用扩展名对应默认程序打开生成文件的物理交付闭环。

## 修改流程

1. 读取完整 `SKILL.md` 和它直接引用的必要资源。
2. 确认是工作区 Skill 还是分发型 Skill，并保持现有目录与元数据约定。
3. 做最小修改；同步更新受影响的脚本、模板或示例。
4. 运行现有检查或最小可执行验证。
5. 仅在该 Skill 已采用版本或变更日志时更新它们；发布和安装需另行明确授权。

## 凭证存储

工作区 Skill 使用的 API Token 与凭证统一存入 `.data/credentials/<skill-name>/`（如 `.data/credentials/<skill-name>/token`）。  
`.data/` 已由根 `.gitignore` 排除，不会进入版本库。  
全局安装（脚本运行时检测不到 `.data/` 目录）时降级到 `~/.config/<skill-name>/token`。

## 安全

Skill 不得绕过根规则的外部写入、隐私、发布和删除确认。涉及凭证、医疗材料或个人信息时，只传递任务所需的最少数据。
