# 工作区自然语言指令与任务解析

本文件涵盖两类场景：
1. **通用任务解析**：收到任意自然语言指令时，将其解析为任务卡并查证关键元素。
2. **显式指令语义**：当用户以”同步””同步任务””任务””记录/沉淀”或”复盘”明确发起操作时，按下方各节解释意图。普通问答或提到这些词不自动触发写入。

所有外部写入仍受根 `AGENTS.md` 安全边界约束。精确命令以对应工具和专项规则为准，本文件不复制 CLI 参数。

## 通用任务解析

收到任意自然语言指令时，先在内部形成任务卡，不要求用户按表单重述：

| 元素 | 含义 |
|---|---|
| 时间 | 事件时间、执行时间和截止日期，三者分别识别 |
| 项目 | 项目名称、简称、Dashboard ID 和工作目录 |
| 动作 | 整理、撰写、评审、修改、汇报、发送等 |
| 对象 | 会议纪要、需求、合同、报告、课件等 |
| 素材 | 附件、链接、录音、转写、笔记、历史文件和知识依据 |
| 产出 | 内容目标、格式、受众、保存位置和完成标准 |
| 执行信息 | 负责人、相关人、截止日期、敏感性和是否需要通知 |

### 解析与查证顺序

1. 优先采用用户本句中的明确表达，其次采用本轮附件和链接，再采用当前对话上下文。
2. 项目按”精确名称或 ID → 已登记简称 → 当前项目 → 上下文”解析；用
   `/api/board` 和 `/api/project/{id}` 查证。多个项目都可能匹配时必须追问。
3. “今天、明天、下周五”等相对时间以当前会话日期和时区换算为绝对日期。
   时间修饰会议、材料或事件名时视为事件时间；修饰”完成、提交、交付”时视为截止日期。
   语义仍会改变素材选择或期限时才追问。
4. 素材按”本轮附件或明确路径 → 对话中已引用文件 → 同日期事件目录 →
   Calendar 对应事件 → 项目知识索引”查找。日历标题只能证明会议存在，不能代替会议内容。
5. 动作和对象共同决定产出。命中专用 Skill 或项目模板时优先使用；否则内部文字产出默认
   Markdown，正式对外文件、PPT、Word 或 PDF 格式不明确时再确认。
6. 默认保存到匹配的 `YYYYMMDD_事件名/`；已有事件目录则复用，没有实际材料或产出时不创建空目录。

### 追问边界

能通过现有文件、Dashboard、日历或上下文唯一确定的内容不要询问。只有以下情况暂停：

- 项目存在多个有效匹配；
- 找不到完成任务所需的实质素材，或候选素材互相冲突；
- 受众或格式会显著改变产出，且无法从”内部/正式对外”判断；
- 涉及发送、发布、删除、覆盖、个人或医疗数据等需要授权的动作；
- 用户明确表述与 `_契约/当前状态.md` 中已有基线存在明显冲突——询问确认后，由用户决定是否更新当前状态。

其余缺省项采用最保守的内部工作默认值，并在结果中说明。执行前只需用一句话复述关键理解；若用户已经说清且任务可直接完成，不把复述变成确认门槛。

### 示例

在 `<YYYY-MM-DD>` 收到”整理今天 `<项目简称>` 的会议纪要”：

- 时间：事件日期 `<YYYY-MM-DD>`，不是截止日期；
- 项目：`<项目名>` / `<project_id>`；
- 动作与产出：依据真实会议素材整理会议纪要；
- 素材：先找本轮附件和同日事件目录，再核对 Calendar；只有会议标题而没有记录时询问素材位置；
- 保存：复用或建立 `<YYYYMMDD>_会议主题/`，按专用会议纪要 Skill 或项目模板生成；
- Dashboard：复用已有任务，或以 `<project_id>:<YYYYMMDD>:会议纪要` 建立进行中任务，产物验证后完成；纪要内提取的行动项不自动写入 Dashboard，待人工完善后由「同步任务」指令触发。

## 工作区初始化 / 新机配置

用于新电脑上手、新协作者接入或工作区软链修复。

**触发场景**：用户输入 `初始化`、`新电脑`、`我是新人`、`配置工作区`、`系统初始化` 或首次使用。

**执行步骤**：
1. **自动恢复根软链接**：后台静默执行 `python3 .system/tools/bootstrap.py`，确保 `AGENTS.md` 和 `CLAUDE.md` 链接完好。
2. **检查看板凭证**：
   - 若已配置：直接读取并向用户回显用户名及看板可用状态；
   - 若未配置：使用通俗大白话向用户索取 API Token（*“请将管理员发放给您的 43 位看板 Token 粘贴发送给我”*），获得后在后台执行 `python3 .system/skills/internal-board/scripts/init.py --token <TOKEN>` 完成一键注册与日历同步。
3. **就绪反馈**：提示用户已就绪，可直接通过自然语言使用各类业务功能（如“看下待办”、“记个任务”、“生成会议纪要”等）。

## 同步

用于核对项目本地状态、Board-Platform 与 Dashboard。

1. 按 `项目运行规则.md` 定位项目，按稳定任务 ID 和 `source_ref` 配对。
2. 读取各端状态与可用时间证据，先列差异。
3. 修改时间只能辅助判断，不能单独决定语义真源；发生冲突时优先采用项目声明的本地状态真源，无法判断则报告待确认。
4. 经授权后按 `开发项目联动规则.md` 幂等更新，并回读验证。
5. 删除、关闭、覆盖或无法回滚的差异不自动处理。

## 同步任务

用于把已经人工确认的会议或事件行动项写入 Dashboard。

- 先定位来源文件并提取项目、负责人、截止日期、内容和稳定 `source_ref`。
- 未经人工确认的会议纪要行动项只保留为草稿。
- 写入方式与回读检查见 `internal-board` Skill §6（source_ref 与准入标准）。
- 输出逐项成功、失败与缺失字段，不用汇总成功掩盖部分失败。

## 任务

用于把用户明确要求登记的自然语言任务写入任务系统。

- 按 `项目运行规则.md` 解析项目、负责人、截止日期和可执行内容。
- 项目有 `docs/.board.json` 时按 `开发项目联动规则.md` 使用同一任务 ID；其他项目只写用户指定的系统。
- 不因纯问答、查找或建议自动建任务。
- 多个项目同样匹配或关键字段会改变归属时再询问。

## 记录 / 沉淀

按 `知识库规则.md` 判断目标形态：

- 离散事实或交付物：新文档。
- 持续演进的基线：更新既有真源。
- 长期行为约束：修改相应层级的规则。
- 高频、可复用且步骤稳定的流程：评估为 Skill。

先读取目标文件并保留现有内容。用户已经明确要求修改规则时，不重复索取同一授权；写入外部系统或扩大范围仍需单独授权。

## 复盘

用于回顾用户指定项目和时间范围，识别重复劳动、纠正、知识缺口、决策变化与未闭环事项。

- 默认产出分析和建议；只有用户明确要求落盘时才创建复盘文档。
- 规则建议进入相应规则真源，项目事实进入当前状态真源，行动项只有在“任务/同步任务”被明确触发时才写入外部系统。
- 证据不足的判断标为待确认，不补写不存在的历史。
