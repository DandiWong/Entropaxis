# 工作流指令

日常业务动作的显式指令语义。通用任务解析见 [`指令解析.md`](指令解析.md)；系统治理类动作见 [`治理指令.md`](治理指令.md)。

## 工作区初始化 / 新机配置

用于新电脑上手、新协作者接入或工作区入口配置自愈。

**触发场景**：用户输入 `初始化`、`新电脑`、`我是新人`、`配置工作区`、`系统初始化`、`配置打开方式`、`修改打开程序` 或首次使用。

**执行步骤**：

1. **自动同步根入口配置**：后台执行 `python3 .system/tools/bootstrap.py`，确保 `AGENTS.md` 和 `CLAUDE.md` 物理同步就绪。
2. **检查看板凭证**：
  - 若已配置：直接读取并向用户回显用户名及看板可用状态；
  - 若未配置：使用通俗大白话向用户索取 API Token（*“请将管理员发放给您的 43 位看板 Token 粘贴发送给我”*），获得后在后台执行看板初始化脚本（如可用）完成一键注册与日历同步。
3. **检测并配置本机文件打开程序（含人类仲裁）**：
  - `.data/templates/file-opener.json` 已存在时，`bootstrap.py` 已完成合并补全，**不得再手工改写该文件**；标记 `arbitrated: true` 的条目为人工决定，任何情况下不覆盖（见 [`控制面布局.md`](控制面布局.md)「`.data/` 写入规约」）。
  - 仅当某格式**尚无任何配置**，或用户显式要求「配置打开方式」/「修改默认打开软件」时，才列举本机候选请用户仲裁，确认后按字段更新该格式条目。
  - 全量重扫须用户显式要求，执行 `python3 .system/tools/bootstrap.py --force-rescan-opener`。
4. **就绪反馈**：提示用户已就绪，可直接通过自然语言使用各类业务功能（如“看下待办”、“记个任务”、“生成会议纪要”等）。

## Tip

当用户指令仅为 `tip`（忽略首尾空白，不区分大小写）时，从 `.data/rules/tips.md` 中回显一条以 `- TIP：` 开头的原文。文件缺失、为空、不可读取或不含有效条目时静默说明无可用 Tip；不得因此修改文件、创建任务或触发其他动作。

## 定位 / 查找文件

用于根据用户意图查找并定位工作区内的特定文件、资料或目录。

1. **触发意图**：见 [`文件交付.md`](文件交付.md) 4.2 场景二的触发词清单，本处不复述。
2. **定位与查证**：在工作区（或项目资料、知识库）中检索匹配的目标路径，核对最新有效版本。
3. **物理动作闭环**：输出路径和简要说明的同时，按《文件交付》第 4 节调用系统打开能力打开该文件或目录。

## 会议纪要

用于根据真实会议材料生成或更新会议纪要。

**触发意图**：`整理会议纪要`、`生成会议纪要`、`写会议纪要`、`会议纪要`。

1. **输入**：按 [`指令解析.md`](指令解析.md) 获取事件时间、项目、素材、受众和格式；缺少转写、笔记等实质材料时询问，日历标题只能证明会议存在。
2. **执行**：调用匹配的会议纪要 Skill 或项目模板生成内容；项目归属与目录见 [`项目组织.md`](项目组织.md)，命名、自检和打开见 [`文件交付.md`](文件交付.md)。
3. **行动项**：纪要中的行动项默认只保留为草稿；只有用户明确触发“同步任务”时，才按 [`看板联动.md`](看板联动.md) 写入外部任务系统。

## 生成或更新工作空间 Tips

用于从已生效的工作空间规则与声明中生成 Tips 更新候选。

1. 先读取 `.data/rules/tips.md`、`.data/templates/registry.md`、根 `AGENTS.md` 及本次涉及的已生效规则；项目材料只在用户明确指定项目时读取。
2. 输出新增、修改、停用候选及每条的真源路径；不得提取凭据、外部系统 ID、个人信息、未确认会议内容、草稿或推断性结论。
3. 默认只生成候选，不直接改写 `.data/rules/tips.md`。用户确认后再最小化更新该文件，并保留已有有效 Tips。
4. Tips 只能描述可验证的操作入口或已生效规则，不得替代项目决策、任务状态或原始资料。

## 同步

用于核对项目本地状态与配置的外部看板。

1. 按 [`项目组织.md`](项目组织.md) 定位项目，按稳定任务 ID 和 `source_ref` 配对。
2. 读取各端状态与可用时间证据，先列差异。
3. 修改时间只能辅助判断，不能单独决定语义真源；发生冲突时优先采用项目声明的本地状态真源，无法判断则报告待确认。
4. 经授权后按 `看板联动.md` 幂等更新，并回读验证。
5. 删除、关闭、覆盖或无法回滚的差异不自动处理。

## 同步任务

用于把已经人工确认的会议或事件行动项写入配置的外部任务看板。

- 先定位来源文件并提取项目、负责人、截止日期、内容和稳定 `source_ref`。
- 未经人工确认的会议纪要行动项只保留为草稿。
- 写入方式与回读检查见团队看板 Skill（source_ref 与准入标准）。
- 输出逐项成功、失败与缺失字段，不用汇总成功掩盖部分失败。

## 任务

用于把用户明确要求登记的自然语言任务写入任务系统。

- 按 [`项目组织.md`](项目组织.md) 解析项目、负责人、截止日期和可执行内容。
- 项目有 `docs/.board.json` 时按 `看板联动.md` 使用同一任务 ID；其他项目只写用户指定的系统。
- 不因纯问答、查找或建议自动建任务。
- 多个项目同样匹配或关键字段会改变归属时再询问。

## 记录 / 沉淀

按 `知识沉淀.md` 判断目标形态：

- 离散事实或交付物：新文档。
- 持续演进的基线：更新既有真源。
- 长期行为约束：修改相应层级的规则。
- 高频、可复用且步骤稳定的流程：评估为 Skill。

先读取目标文件并保留现有内容。用户已经明确要求修改规则时，不重复索取同一授权；写入外部系统或扩大范围仍需单独授权。

## 复盘

用于回顾用户指定项目和时间范围，识别重复劳动、纠正、知识缺口、决策变化与未闭环事项。

- 默认产出分析和建议；只有用户明确要求落盘时才创建复盘文档。
- 规则建议进入相应规则真源，项目事实进入当前状态真源，行动项只有在”任务/同步任务”被明确触发时才写入外部系统。
- 证据不足的判断标为待确认，不补写不存在的历史。
- **案例收录**：本轮复盘中导致规则或工具变更的失效、以及正确路径非显然的判断，按 [`.data/rules/规则案例库.md`](../../.data/rules/规则案例库.md) 的收录门禁与条目格式各记一条；该库是规则的存在依据索引，退役核验凭此。文件缺失时视为空库，先创建再写入，不阻断复盘。
- **路由命中率抽查**：涉及规则遵循问题的复盘，额外核查回顾期内是否存在”本应命中某机制规则但未读取/未执行”的案例（含转述、意译等语义命中但被漏检的情形，`route_map.json` 只覆盖字面触发词，天然覆盖不到这类漏检）；发现新的高频字面触发词时，作为规则建议登记到 `route_map.json`（真源见 `route_map.json` 的 `_meta.source_of_truth`），不得直接编造未在规则正文出现过的关键词。

## 报销 / 整理发票

用于把散落的发票与报销凭据检索、归总、折算并生成当日台账。

1. **触发意图**：用户输入 `报销`、`整理发票`、`报销归总`、`发票归总`、`报销初始化` 等。
2. **判据与账目红线**：见 [`财务报销.md`](财务报销.md)——收集范围、增量 Baseline、六条账目完整性红线与归档状态流转。
3. **执行**：唤起 `invoice-collector` Skill 完成归位、分类、汇率折算与 `清单.md` 生成。
4. **物理动作闭环**：按《文件交付》第 4 节调用系统默认程序打开生成的 `清单.md`。
