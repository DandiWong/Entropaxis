# 工作流指令

日常业务动作的显式指令语义。通用任务解析见 [`指令解析.md`](指令解析.md)；系统治理类动作见 [`治理指令.md`](治理指令.md)。

## 工作区初始化 / 新机配置

用于新电脑上手、新协作者接入或工作区入口配置自愈。**触发场景**：`初始化`、`新电脑`、`我是新人`、`配置工作区`、`配置打开方式` 等。

1. **自动同步根入口**：执行 `python3 .system/tools/bootstrap.py`，物理同步 `AGENTS.md` 和 `CLAUDE.md`。
2. **看板按需配置**：初始化不索取看板 Token，随首次使用看板 Skill 时触发按需补全。
3. **检测文件打开程序**：`.data/templates/file-opener.json` 标记 `arbitrated: true` 的人工配置不覆盖，未配置格式列举候选由人工仲裁。
4. **就绪反馈**：提示工作区就绪，可直接执行日常业务指令。
## 事务 / 新事务

用于为一件真实事件、特性研发或独立交付物定位既有事务胶囊，或在合理项目目录下新建一个。

1. **触发意图**：`事务`、`新事务`、`起个事务`、`建个事务`、`开个事务` 等，后接主题描述。
2. **先定位后创建**：按 [`指令解析.md`](指令解析.md) 解析项目与主题（归属以 [`项目组织.md`](项目组织.md) 注册表真源为准），在目标项目内检索同主题既有胶囊，命中即复用并说明路径，**严禁为同一件事重复建容器**；项目候选不唯一时先确认，不擅自新建。
3. **命名与结构**：命名与 Front Matter 遵循 [`文件交付.md`](文件交付.md) 2.1–2.2 节；子目录遵循《项目组织》懒创建铁律。可直接建容器，或调 `python3 .system/tools/init_capsule.py <父目录> <中文主题> --id <ID> --mode full|light|research` 生成阶段骨架；仅说"起个事务"未要阶段文档时默认只建容器。
4. **物理动作闭环**：按《文件交付》第 4 节通过 `open_file.py` 打开该胶囊目录。

## 自定义角色

用于在会话内以交互问答为认知模态或自定义角色配置承载 CLI 与模型。

- **触发意图**：用户输入 `自定义角色`、`配置角色`、`角色配置`、`配置角色承载`、`换个模型` 等。
- **探测候选**：执行 `python3 .system/tools/setup_agents.py --scan --json` 获取本机已安装 Agent CLI 与各角色推荐预设；配置文件缺失时先引导初始化。
- **三步问答**：依次请用户选择——角色（5 大标准认知模态、既有自定义角色或新建）、agent（内置 Subagent 与已安装外置 CLI，附当前配置与推荐预设）、模型（条件适用：`subagent` 无模型概念跳过；有 `--model` 语义的 CLI 列出预设模型候选并允许自由输入）；每轮写入与回读完成后返回角色选择问答继续下一角色，角色候选常驻「结束」选项，选中即退出循环并汇总本轮全部生效变更。
- **写入与回读**：组装启动命令后执行 `python3 .system/tools/setup_agents.py --set-role <角色> <CLI> "<命令>"` 原子更新 [.data/templates/workspace-config.md](../../.data/templates/workspace-config.md) 角色表（merge-only，仅该表段落；新建角色职责定位默认「业务协作」，需完整职责时按 4 列规范补写该行，不触碰其他章节）；随后执行 `--verify` 回显生效状态，降级语义见 [`角色协作.md`](角色协作.md) 调度契约。

## Tip

当用户指令仅为 `tip`（忽略首尾空白，不区分大小写）时，从 `.data/rules/tips.md` 中回显一条以 `- TIP：` 开头的原文。文件缺失、为空、不可读取或不含有效条目时静默说明无可用 Tip；不得因此修改文件、创建任务或触发其他动作。

## 定位 / 查找文件

用于根据用户意图查找并定位工作区内的特定文件、资料或目录。触发词见 [`文件交付.md`](文件交付.md) 4.2 场景二清单。

在工作区（或项目资料、知识库）检索目标路径并核对最新有效版本；输出路径与简要说明的同时，按《文件交付》第 4 节通过 `open_file.py` 打开该文件或目录。

## 生成或更新工作空间 Tips

用于从已生效规则与声明中提炼 Tips 候选。

1. 读取 `.data/rules/tips.md`、`.data/templates/registry.md`、根 `AGENTS.md` 及已生效规则；只生成候选不直接改写，人工确认后最小化更新。
2. 严禁提取凭据、外部系统 ID、个人隐私、草稿或推断性结论；Tips 仅描述可验证入口，不替代项目决策。
## 同步

用于核对项目本地状态与配置的外部看板。

1. 按 [`项目组织.md`](项目组织.md) 定位项目，按稳定任务 ID 和 `source_ref` 配对。
2. 读取各端状态与可用时间证据，先列差异。
3. 修改时间只能辅助判断，不能单独决定语义真源；发生冲突时优先采用项目声明的本地状态真源，无法判断则报告待确认。
4. 经授权后按 `看板联动.md` 幂等更新，并回读验证。
5. 删除、关闭、覆盖或无法回滚的差异不自动处理。

## 同步任务

用于把已人工确认的会议或事件行动项写入配置的外部任务看板。

- 定位来源文件并提取项目、负责人、截止日期、内容和稳定 `source_ref`；未确认行动项仅保留为草稿。
- 写入方式与回读检查见已安装团队看板 Skill（自身 `SKILL.md`）。输出逐项成功与缺失字段，不掩盖部分失败。
## 任务

用于把用户明确要求登记的自然语言任务写入任务系统。

- 按 [`项目组织.md`](项目组织.md) 解析项目、负责人、截止日期和可执行内容。
- 项目有 `docs/.board.json` 时按 `看板联动.md` 使用同一任务 ID；其他项目只写用户指定的系统。
- 不因纯问答、查找或建议自动建任务；多个项目同样匹配或关键字段会改变归属时再询问。

## 记录 / 沉淀

按 `知识沉淀.md` 判断目标形态。**触发意图**：`记录`、`沉淀`、`沉到` 等。

- 离散事实或交付物：新文档。
- 持续演进的基线：更新既有真源。
- 长期行为约束：修改相应层级的规则。
- 高频、可复用且步骤稳定的流程：评估为 Skill。

先读取目标文件并保留现有内容。用户已经明确要求修改规则时，不重复索取同一授权；写入外部系统或扩大范围仍需单独授权。

## 记为案例

用于在纠偏发生的当场把一次判断留档，不必等到复盘再回忆。

1. **触发意图**：用户输入 `记为案例`、`记个案例`、`这条记下来`、`收录案例`、`记入案例库`、`别再犯` 等。
2. **门禁与格式**：一律以 [`.data/rules/规则案例库.md`](../../.data/rules/规则案例库.md) 正文声明为准（正/反面各自的收录边界、四段式条目、单条行数上限），本节不复述；不满足门禁时说明理由并不写入。文件缺失时先创建再写入，不阻断。
3. **写入约束**：该库 `policy: append-only`，只追加不重写既有条目；`归属` 填当前已生效的规则或工具，尚无归属时写 `待归属`，即为下次复盘的升格候选。
4. **不得自判**：未获用户显式指令不得写入——"这次算不算案例"是主观裁定，模型自判会把日常照章执行灌进库里，稀释退役核验依据。

## 复盘

用于回顾项目和时间范围，识别重复劳动、纠偏、知识缺口、决策变化与未闭环事项。**触发意图**：`复盘`、`回顾下` 等。

- 默认产出分析和建议，明确要求时才落盘。规则建议进规则真源，项目事实进状态真源。
- **案例收录**：导致规则/工具变更的失效按 [`.data/rules/规则案例库.md`](../../.data/rules/规则案例库.md) 记入一条。
- **路由抽查**：核查是否存在应命中某机制但漏检案例，新高频词按真源更新 `route_map.json`。

## 报销 / 整理发票

用于把散落的发票与报销凭据检索、归总、折算并生成当日台账。

1. **触发意图**：`报销`、`整理发票`、`报销归总`、`发票归总`、`报销初始化`、`发票该报` 等。
2. **执行**：按 [`财务报销.md`](财务报销.md) 收集与判据，调用 `invoice-collector` Skill 生成 `清单.md` 并通过 `open_file.py` 打开。
