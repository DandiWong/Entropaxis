# 工作流指令

日常业务动作的显式指令语义。通用任务解析见 [`指令解析.md`](指令解析.md)；系统治理类动作见 [`治理指令.md`](治理指令.md)。

## 工作区初始化 / 新机配置

用于新电脑上手、新协作者接入或工作区入口配置自愈。**触发场景**：`初始化`、`新电脑`、`我是新人`、`配置工作区`、`配置打开方式` 等。

1. **自动同步根入口**：执行 `python3 .entropaxis/tools/bootstrap.py`，物理同步 `AGENTS.md` 和 `CLAUDE.md`。
2. **看板按需配置**：初始化不索取看板 Token，随首次使用看板 Skill 时触发按需补全。
3. **检测文件打开程序**：`.entropaxis/data/templates/file-opener.json` 标记 `arbitrated: true` 的人工配置不覆盖，未配置格式列举候选由人工仲裁。
4. **角色本地候选与授权边界**：Bootstrap 在渲染、盖章后只显示外置 profile 的本机 CLI/无交互候选；这**不是模型有效性验证**，不会选择 profile 或写入 `roles.yaml`。如需实测，先在对话中说明可能使用的提供商与成本，取得明确同意后才执行 `python3 .entropaxis/tools/setup_agents.py --check-preferences --authorize-model-check --authorization-event '<用户确认>' [--json]`；拒绝或未回答时保留既有选择，新实例保持 `null`。

## 事务 / 新事务

用于为一件真实事件、特性研发或独立交付物定位既有事务胶囊，接续研讨或在合理项目目录下新建。

1. **触发意图**：`事务`、`新事务`、`起个事务`、`建个事务`、`开个事务`，以及`继续讨论 A [事务/胶囊]`、`讨论 A 事务`、`谈谈 A 胶囊`等针对具体事务主题的研讨接续。
2. **三级检索阶梯（胶囊优先铁律）**：
   - **第一级（胶囊定位）**：优先执行 `python3 .entropaxis/tools/find_capsule.py <主题词>`。命中即复用该胶囊，只读取最新进展并在对话中反馈以开展研讨，**严禁为同一件事重复建容器；不自动调用 open_file 打开目录或文件**（仅在用户显式要求「打开」时才调用）；
   - **第二级（零散降级）**：未命中胶囊时，才使用 `grep`/`glob`（或 `multi_grep`/`find`）检索项目与工作区历史零散文件与文档；
   - **第三级（无产物交互创建）**：第二级仍无结果（确认真无相关积累），主动向用户说明未检索到历史胶囊与材料，**交互询问是否为此创建新事务胶囊**（经确认后再调用 `init_capsule.py`）。
3. **命名与结构**：命名与 Front Matter 遵循 [`文件交付.md`](文件交付.md) 2.1–2.2 节；子目录遵循《项目组织》懒创建铁律。可直接建容器，或调 `python3 .entropaxis/tools/init_capsule.py <父目录> <中文主题> --id <ID> --mode full|light|research` 生成阶段骨架；仅说"起个事务"未要阶段文档时默认只建容器。
4. **物理动作闭环**：仅在显式新建胶囊或用户明确要求「打开」时通过 `open_file.py` 打开；定位既有胶囊研讨时不自动打开。

## 调研 / 方案调研

用于对技术选型、前沿探索、临床医药、行业竞品、管理流程等进行系统性事实查证与最优方案制定。

1. **触发意图**：`调研`、`做调研`、`出调研`、`调研报告`、`技术选型`、`最优方案`、`帮我调研` 等，后接调研主题。日常"查一下某文件/某个值"属定位查找或普通问答，不触发本机制。
2. **门禁与准则**：严格执行 [`方案调研.md`](方案调研.md) 规则（强制联网检索取证、横向对比 2~3 个路线、严格区分事实与推断）。
3. **输出与落盘**：按《方案调研》第四节四段式输出。`出调研`、`做调研`、`调研报告` 属《文件交付》第 1 节落盘触发词，沉淀为胶囊内 `01_调研.md` 并在回复中给出路径；其余说法先在对话内输出，再询问是否落盘。

## 角色清单 / 自定义角色
用于查看角色承载全景，或为认知模态与自定义角色配置承载 CLI 与模型参数。

- **触发意图**：`角色清单`、`查看角色`、`角色列表`、`自定义角色`、`配置角色`、`角色配置`、`换个模型`、`调超时`、`改职责`、`删除角色` 等。
- **查看清单**：执行 `python3 .entropaxis/tools/setup_agents.py --list [--json]`，回显每角色的门禁（硬/软）、职责、**有序**偏好及当前选中的序号（CLI/模型/超时/PATH 本地状态）；清单中发现配置问题按 `--verify` 裁决。
- **局部更新**（命令其余偏好不动）：
  - 换已选模型：`--set-model <角色> <模型>`；
  - 调选中偏好超时：`--set-timeout <角色> <秒>`（硬门禁 ≤1800，全员 ≤7200）；上述两项可加 `--preference <序号>` 定向更新其他位置；
  - 改职责描述：`--set-duty <角色> "<职责>"`。
- **偏好编辑**：`--set-preference <角色> <序号> <agent> <model>` 替换或追加配对，保留模型 provider 前缀；`--move-preference <角色> <原序号> <新序号>` 调整顺序；`--remove-preference <角色> <序号>` 默认预览，确认后加 `--yes` 删除。`--set-role <角色> <CLI> "<命令>"` 仍支持 `||` 分隔的自定义 argv；`subagent` 改回内置承载。写入命令可加 `--dry-run` 预览。
- **标识命名**：工具新增配对使用 `<角色小写>-<数字>`，如 `architecture-1`、`architecture-2`；冲突时取下一个空闲数字。标识保持稳定，移动偏好不重命名；实际顺序仍由 `preferences` 决定。自定义校验命令如 `builder-verify` 保留用途名称。
- **两阶段检测**：`--detect-preferences` 仅查本地候选，不选择、不写配置。先在对话中告知提供商与可能成本，获用户明确授权后，才执行 `--check-preferences --authorize-model-check --authorization-event '<用户确认>'` 做最小真实调用，按序选首个有效回显并记录序号；全部失败保留旧选择。未授权、拒绝或无回答时不调用模型，已有配置不动，新实例保持 `null`。
- **迁移**：旧角色 fallback 链仅在显式 `--migrate-preferences` 或获授权的写入操作中迁移；本地检测和未授权检查不迁移。偏好列表是唯一顺序，选中 profile 必须属于该列表；序号从 1 起，不限制为三级。
- **删除角色**：`--remove-role <角色>` 默认 dry-run 预览，确认后加 `--yes` 落盘；标准 7 角色受保护不可删除（停用外置承载改用 `--set-role <角色> subagent ""`），删除后自动回收仅该角色引用的 profile。
- **边界**：自定义角色（英文 PascalCase）经 `--set-role` 写入后仅作承载声明——`dispatch_role.py --role` 限 7 个标准认知模态，不调度自定义角色；确需新认知模态走《治理指令》「系统演进」。硬门禁不因偏好顺序或检测结果改变。

## 定位 / 查找文件

用于根据用户意图查找并定位工作区内的特定文件、资料或目录。触发词见 [`文件交付.md`](文件交付.md) 4.2 场景二清单。

在工作区（或项目资料、知识库）检索目标路径并核对最新有效版本；输出路径与简要说明的同时，按《文件交付》第 4 节通过 `open_file.py` 打开该文件或目录。

**检索一律先走工具，不手写遍历命令**：

```bash
python3 .entropaxis/tools/find_capsule.py <主题词>              # 默认工作区范围，实时
python3 .entropaxis/tools/find_capsule.py <主题词> --scope machine  # 扩到全机器，查系统索引
```

该工具按项目注册表的「口语别名」把检索范围收敛到项目主目录，再按平台选后端（`fd`→`find`；机器范围用 Spotlight/Everything/plocate），结果只保留胶囊目录并按日期倒排。**严禁改用手写的 `find`/`glob` 全盘遍历**（一次返回数百条路径）。

后端与新鲜度边界：工作区范围永不读索引（刚建的胶囊立即可见）；机器范围读系统索引，可能滞后且在 macOS 上不覆盖隐藏目录，工具会在降级或有盲区时显式留痕，须如实转达给用户。缺 `fd` 时自动降级为 `find` 并给出安装命令；`--doctor` 单独报告本机可用后端。

## 生成或更新工作空间 Tips

用于从已生效规则与声明中提炼 Tips 候选。

1. 读取 `.entropaxis/data/rules/tips.md`、`.entropaxis/data/templates/registry.yaml`、根 `AGENTS.md` 及已生效规则；只生成候选不直接改写，人工确认后最小化更新。
2. 严禁提取凭据、外部系统 ID、个人隐私、草稿或推断性结论；Tips 仅描述可验证入口，不替代项目决策。

## 同步

用于核对项目本地状态与配置的外部看板。按 [`项目组织.md`](项目组织.md) 定位项目并配对 ID；先列差异，修改时间仅辅助判断，冲突时以本地真源为准；经授权后按 `看板联动.md` 幂等更新；删除/覆盖等不可逆差异不自动处理。

## 同步任务

用于把已人工确认的行动项写入外部看板。定位来源提取项目、负责人与截止日期（未确认仅保留草稿）；按团队看板 Skill 写入并回读，不掩盖部分失败。

## 任务

用于把用户明确要求的任务写入系统。按《项目组织》解析要素；有 `docs/.board.json` 时按《看板联动》使用同一 ID；不因纯问答或建议自动建任务。

## 记录 / 沉淀

按《知识沉淀》「沉淀形态判定模型」判断目标形态，涉及规则/工具/Skill 时转《治理指令》「系统演进」。**触发意图**：`记录`、`沉淀`、`沉到` 等。

先读取目标文件并保留现有内容。用户已经明确要求修改规则时，不重复索取同一授权；写入外部系统或扩大范围仍需单独授权。

## 记为案例

用于在纠偏发生的当场把一次判断留档，不必等到复盘再回忆。

1. **触发意图**：用户输入 `记为案例`、`记个案例`、`这条记下来`、`收录案例`、`记入案例库`、`别再犯` 等。
2. **门禁与格式**：一律以 [`.entropaxis/data/rules/规则案例库.md`](../data/rules/规则案例库.md) 正文声明为准（正/反面各自的收录边界、四段式条目、单条行数上限），本节不复述；不满足门禁时说明理由并不写入。文件缺失时先创建再写入，不阻断。
3. **写入约束**：该库 `policy: append-only`，只追加不重写既有条目；`归属` 填当前已生效的规则或工具，尚无归属时写 `待归属`，即为下次复盘的升格候选。
4. **不得自判**：未获用户显式指令不得写入——"这次算不算案例"是主观裁定，模型自判会把日常照章执行灌进库里，稀释退役核验依据。

## 复盘

用于回顾项目和时间范围，识别重复劳动、纠偏、知识缺口、决策变化与未闭环事项。**触发意图**：`复盘`、`回顾下` 等。

- 默认产出分析和建议，明确要求时才落盘。规则建议进规则真源，项目事实进状态真源。
- **案例收录**：导致规则/工具变更的失效按 [`.entropaxis/data/rules/规则案例库.md`](../data/rules/规则案例库.md) 记入一条。

## 报销 / 整理发票

用于把散落的发票与报销凭据检索、归总、折算并生成当日台账。

1. **触发意图**：`报销`、`整理发票`、`报销归总`、`发票归总`、`报销初始化`、`发票该报` 等。
2. **执行**：唤起 `invoice-collector` Skill；收集范围、账目红线与台账结构均以该 Skill 为唯一真源，本节不复述。
