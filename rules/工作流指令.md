# 工作流指令

日常业务动作的显式指令语义。通用任务解析见 [`指令解析.md`](指令解析.md)；系统治理类动作见 [`治理指令.md`](治理指令.md)。

## 工作区初始化 / 新机配置

用于新电脑上手、新协作者接入或工作区入口自愈。**触发场景**：`初始化`、`新电脑`、`我是新人`、`配置工作区`、`配置打开方式` 等。

1. **同步入口**：执行 `python3 .entropaxis/tools/bootstrap.py` 同步 `AGENTS.md` 和 `CLAUDE.md`。
2. **按需配置**：看板 Token 首次使用按需补全；`.entropaxis/data/templates/file-opener.json` 人工配置不覆盖。
3. **角色候选与授权**：Bootstrap 仅展示本机可执行候选（不写 `roles.yaml`）；真实模型调用须先说明成本取得明确同意后，才执行 `setup_agents.py --check-preferences --authorize-model-check --authorization-event '<用户确认>'`，只报告不写配置。

## 事务 / 新事务

用于为一件真实事件、特性研发或独立交付物定位既有事务胶囊，接续研讨或在合理项目目录下新建。

1. **触发意图**：`事务`、`新事务`、`起个事务`、`建个事务`、`开个事务`，以及`继续讨论 A [事务/胶囊]`、`讨论 A 事务`、`谈谈 A 胶囊`等针对具体事务主题的研讨接续。
2. **三级检索阶梯（胶囊优先铁律）**：
   - **第一级（胶囊定位）**：优先执行 `python3 .entropaxis/tools/find_capsule.py <主题词>`。命中即复用该胶囊，只读取最新进展并在对话中反馈以开展研讨，**严禁为同一件事重复建容器；不自动调用 open_file 打开目录或文件**（仅在用户显式要求「打开」时才调用）；
   - **第二级（零散降级）**：未命中胶囊时，才使用 `grep`/`glob`（或 `multi_grep`/`find`）检索项目与工作区历史零散文件与文档；
   - **第三级（无产物交互创建）**：第二级仍无结果（确认真无相关积累），主动向用户说明未检索到历史胶囊与材料，**交互询问是否为此创建新事务胶囊**（经确认后再调用 `init_capsule.py`）。
3. **命名与结构**：命名与 Front Matter 遵循 [`文件交付.md`](文件交付.md) 2.1–2.2 节；子目录遵循《项目组织》懒创建铁律。可直接建容器，或调 `python3 .entropaxis/tools/init_capsule.py <父目录> <中文主题> --id <ID> --mode full|light|research` 生成阶段骨架；仅说"起个事务"未要阶段文档时默认只建容器。开工不再预先开段：角色工作由调度自动计段（`dispatch_role.py run --capsule <胶囊目录>` 自开自结）；Manager 自己动手时才开 Manager 段（`--start-task --name <事务>`），并在等待用户前 `--end-task --evidence <本段产出物>` 结段。
4. **物理动作闭环**：新建胶囊与阶段文档落盘不自动打开（按《文件交付》§4 回复中给出路径）；仅在用户明确要求「打开」时才通过 `open_file.py` 打开。

## 调研 / 方案调研

用于对技术选型、前沿探索、临床医药、行业竞品、管理流程等进行系统性事实查证与最优方案制定。

1. **触发意图**：`调研`、`做调研`、`出调研`、`调研报告`、`技术选型`、`最优方案`、`帮我调研` 等，后接调研主题。日常"查一下某文件/某个值"属定位查找或普通问答，不触发本机制。
2. **门禁与准则**：严格执行 [`方案调研.md`](方案调研.md) 规则（强制联网检索取证、横向对比 2~3 个路线、严格区分事实与推断）。
3. **输出与落盘**：按《方案调研》第四节四段式输出。`出调研`、`做调研`、`调研报告` 属《文件交付》第 1 节落盘触发词，沉淀为胶囊内 `01_调研.md` 并在回复中给出路径；其余说法先在对话内输出，再询问是否落盘。

## 提取需求 / 需求提炼

用于从会议逐字稿或项目文档中提取共识与约定功能点，形成标准需求清单与功能规格说明。

1. **触发意图**：`提取需求`、`提炼需求`、`梳理需求`、`从逐字稿提需求`、`总结需求清单`、`导出需求清单` 等。
2. **四步闭环**：
   - **定位素材**：优先定位目标项目下指定文档或最近会议胶囊的 `*逐字稿.txt`（歧义时列出候选确认）；
   - **编号继承（模式 A 铁律）**：检索 `02_产品设计/01_需求清单/` 既有清单，按 `REQ-{{yyyymmdd}}-NN` 继承顺番（同日接续最大序号，不同日期以当日 `01` 起编，严禁盲目归零）；
   - **调度 Researcher 提炼共识**：按《角色协作》调度 **Researcher** 提取达成共识或明确约定的功能点，过滤寒暄、发散设想与分歧未决项；
   - **结构化成文落盘**：默认落盘于目标项目 `02_产品设计/01_需求清单/YYYYMMDD_主题需求清单/01_需求清单.md`（或胶囊内），含「需求矩阵总览」及各小节详细规格，严格遵循六段式契约（用户故事、输入、处理与条件分支、输出、边界与异常处理、优先级）。

## 角色清单 / 自定义角色
用于查看角色承载全景，或为认知模态与自定义角色配置承载 CLI 与模型参数。

- **触发意图**：`角色清单`、`查看角色`、`角色列表`、`自定义角色`、`配置角色`、`角色配置`、`换个模型`、`调超时`、`改职责`、`删除角色` 等。
- **查看清单**：执行 `python3 .entropaxis/tools/setup_agents.py --list`，回显每角色的门禁（硬/软）、职责与**有序**偏好（CLI/模型/超时/PATH 本地状态）；清单中发现配置问题按 `--verify` 裁决。
- **局部更新**（命令其余偏好不动）：
  - 换已选模型：`--set-model <角色> <模型>`；
  - 调超时：`--set-timeout <角色> <秒>`（默认写角色级，该角色全部偏好生效；硬门禁按角色设上限 Reviewer ≤3600 / Maintainer ≤1800，全员 ≤7200）；定向覆盖单个偏好加 `--preference <序号>`；
  - 改职责描述：`--set-duty <角色> "<职责>"`。
- **偏好编辑**：`--set-preference <角色> <序号> <agent> <model>` 替换或追加配对，保留模型 provider 前缀；`--move-preference <角色> <原序号> <新序号>` 调整顺序；`--remove-preference <角色> <序号>` 默认预览，确认后加 `--yes` 删除。`--set-role <角色> <CLI> "<命令>"` 仍支持 `||` 分隔的自定义 argv；`subagent` 改回内置承载。写入命令可加 `--dry-run` 预览。
- **标识命名**：工具新增配对使用 `<角色小写>-<数字>`，如 `architecture-1`、`architecture-2`；冲突时取下一个空闲数字。标识保持稳定，移动偏好不重命名；实际顺序仍由 `preferences` 决定。自定义校验命令如 `builder-verify` 保留用途名称。**已被胶囊档案 `command_profile` 引用的标识不可改名或删除**（删了历史指派无法复跑，`dispatch_role.py run --assignment` 直接报错）；`--gc` 只回收无任何引用的孤儿 profile。
- **两阶段检测**：`--detect-preferences` 仅查本地候选，不选择、不写配置。先在对话中告知提供商与可能成本，获用户明确授权后，才执行 `--check-preferences --authorize-model-check --authorization-event '<用户确认>'` 做最小真实调用，只报告各偏好实测结果，不写配置；要换默认承载由用户调整 `preferences` 顺序。未授权、拒绝或无回答时不调用模型。
- **迁移**：旧角色 fallback 链仅在显式 `--migrate-preferences` 或获授权的写入操作中迁移；本地检测和未授权检查不迁移。偏好列表是唯一顺序；序号从 1 起，不限制为三级。
- **删除角色**：`--remove-role <角色>` 默认 dry-run 预览，确认后加 `--yes` 落盘；标准 7 角色受保护不可删除（停用外置承载改用 `--set-role <角色> subagent ""`，即 `preferences: []`），删除后自动回收仅该角色引用的 profile。
- **边界**：自定义角色（英文 PascalCase）经 `--set-role` 写入后仅作承载声明——`dispatch_role.py --role` 限 7 个标准认知模态，不调度自定义角色；确需新认知模态走《治理指令》「系统演进」。硬门禁不因偏好顺序或检测结果改变。

## 定位 / 查找文件

用于根据用户意图查找并定位特定文件或目录。触发词见 [`文件交付.md`](文件交付.md) 4.2 场景二清单。

检索一律走 `python3 .entropaxis/tools/find_capsule.py <主题词> [--scope machine]`（默认实时查项目主目录，查全机加 `--scope machine`；严禁 `find`/`glob` 全盘遍历）；核对最新有效版本后，按《文件交付》第 4 节通过 `open_file.py` 打开该文件或目录。缺 `fd` 时自动降级为 `find` 并留痕。
## 生成或更新工作空间 Tips

用于从已生效规则与声明中提炼 Tips 候选。

1. 读取 `.entropaxis/data/rules/tips.md`、`.entropaxis/data/templates/registry.yaml`、根 `AGENTS.md` 及已生效规则；只生成候选不直接改写，人工确认后最小化更新。
2. 严禁提取凭据、外部系统 ID、个人隐私、草稿或推断性结论；Tips 仅描述可验证入口，不替代项目决策。

## 同步

用于核对项目本地状态与配置的外部看板。按 [`项目组织.md`](项目组织.md) 定位项目并配对 ID；先列差异，修改时间仅辅助判断，冲突时以本地真源为准；经授权后按 `看板联动.md` 幂等更新；删除/覆盖等不可逆差异不自动处理。

## 同步任务

用于把已人工确认的行动项写入外部看板。按团队看板 Skill 写入并回读，不掩盖部分失败；未确认项仅保留草稿。
## 任务

用于把用户明确要求的任务写入系统。按《项目组织》解析要素；有 `docs/.board.json` 时按《看板联动》使用同一 ID；不因纯问答或建议自动建任务。

## 记录 / 沉淀

按《知识沉淀》「沉淀形态判定模型」判断目标形态，涉及规则/工具/Skill 时转《治理指令》「系统演进」。**触发意图**：`记录`、`沉淀`、`沉到` 等。

先读取目标文件并保留现有内容。用户已经明确要求修改规则时，不重复索取同一授权；写入外部系统或扩大范围仍需单独授权。

## 记为案例

用于在纠偏发生的当场把一次判断留档，不必等到复盘再回忆。

1. **触发意图**：用户输入 `记为案例`、`记个案例`、`这条记下来`、`收录案例`、`记入案例库`、`别再犯` 等。
2. **门禁与格式**：一律以 [`.entropaxis/data/rules/规则案例库.md`](../data/rules/规则案例库.md) 正文声明为准（正/反面各自的收录边界、四段式条目、单条行数上限），本节不复述；不满足门禁时说明理由并不写入。文件缺失时先创建再写入，不阻断。
3. **写入约束**：该库 `policy: append-only`，只追加不重写既有条目；`归属` 填当前已生效的规则或工具，尚无归属时写 `待归属`，即为下次复盘的升格候选。
4. **不得自判**：未获用户显式指令不得写入——"这次算不算案例"是主观裁定，模型自判会把日常照章执行灌进库里，稀释退役核验依据。

## 复盘

用于回顾项目和时间范围，识别重复劳动、纠偏、知识缺口与未闭环事项。默认产出分析和建议，明确要求时才落盘。导致规则/工具变更的失效按 [`.entropaxis/data/rules/规则案例库.md`](../data/rules/规则案例库.md) 记入。

## 报销 / 整理发票

用于把散落的发票与报销凭据检索、归总、折算并生成当日台账。

1. **触发意图**：`报销`、`整理发票`、`报销归总`、`发票归总`、`报销初始化`、`发票该报` 等。
2. **执行**：唤起 `invoice-collector` Skill；收集范围、账目红线与台账结构均以该 Skill 为唯一真源，本节不复述。

## 工时 / 记工时 / 汇总工时

1. **触发意图**：`开始事务`、`记工时`、`登记工时`、`工时统计`、`汇总工时` 等。
2. **执行**：
   - **自动计量**：分角色段和 Manager 段（见《角色协作》）。角色段由 `dispatch_role.py run --capsule <胶囊目录>` 自开自结，失败或超时记 `failed` 段（计机时不计有效工时）；Manager 段开工前 `--start-task`、等待用户前 `--end-task --evidence <本段产出物>`。产生 `worklog_refs` 自动调同步 Skill 触发扫描入账；
   - **补登与覆盖**：补登只用于人工：`--log-time 1h23m --actor human --stage <阶段> --summary …`；覆盖调 `--override <ref> [--spent 1h23m] [--stage 02_方案] --reason <原因>`；
   - **汇总**：调 `aggregate_worklog.py`，按有效工时 / 机时 / actor 分列，显示 H:MM:SS，输出交周报/汇报引用。
