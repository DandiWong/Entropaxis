# 系统自检 (Entropaxis Self-Check)

本 Skill 是《治理指令》「系统自检」机制的执行体。规则侧只保留触发意图与本 Skill 路由，
检查步骤与产物契约在此维护。

规则真源：
- [`../../rules/治理指令.md`](../../rules/治理指令.md)「系统自检」（触发与范围）
- [`../../rules/00_元规则.md`](../../rules/00_元规则.md)（第一遍的核对基准）
- [`../../rules/01_根系统治理.md`](../../rules/01_根系统治理.md)（第二遍的流程与完成标准）；[`../../rules/系统演进准则.md`](../../rules/系统演进准则.md)（第 7 节多状态求值）
- [`../../rules/软件工程.md`](../../rules/软件工程.md)「检查按影响选」（报告的四段式输出契约）

---

## 1. 检查范围

`.entropaxis/` 各子目录（清单以 `lint_workspace.py` 的 `SYSTEM_REQUIRED_DIRECTORIES` 为准，
不在此复制会漂移的名单）及其部署产物（根 `AGENTS.md`/`CLAUDE.md`）。

递归核验全工作区项目 `AGENTS.md`/`CLAUDE.md` 的结构契约（单锚点回链、零废弃引用、薄壳纯净度、
声明外置悬空兜底），但**不评判项目业务内容本身**。

不评判实例数据与各业务项目的业务内容；实例声明的结构、来源与落地状态仍由体检核验。

---

## 2. 执行流水线

普通「系统自检」运行已有门禁并报告不足，不默认进入覆盖补齐模式。
「自检补全」或明确要求检查覆盖并补全时，执行下方 2.1 节；仅询问该指令含义不触发写入。

一条命令跑完三遍检查并装配报告：

```bash
python3 .entropaxis/tools/report_selfcheck.py
```

该工具内部串起三遍检查与自动改写，退出码 0=全绿、1=有阻断项：

| 遍次 | 内容 | 承接 |
|---|---|---|
| 第一遍 | 元规则九条公理机械承接核对 | 核对 `AXIOM_COVERAGE` 与本轮体检项执行证据；缺项阻断，无承接的公理报未验证 |
| 第二遍 | 双重体检门禁（单测 + 工作区体检） | `unittest discover` + `lint_workspace.py --json` |
| 第三遍 | 收件方视角求值（新克隆工作区实跑初始化链路） | `check_distribution.py --json` |
| 附加 | CLAUDE.md 违规自动改写为标准薄壳 | `lint_workspace.py --fix-claude-md` |

需要机器可读结果时加 `--json`；需要跳过自动改写时加 `--no-fix-claude-md`。
子进程超时、异常、非零退出与零测试发现均阻断；分发阻断和建议明细完整进入报告，归类见第 4 节。

第三遍内部要再跑一遍全量单测，慢机器上耗时可达分钟级。超时不再写死：分发检查接受
`--timeout <秒>` 或 `ENTROPAXIS_SUBPROCESS_TIMEOUT`（默认 900s），自检内部按遍次给
体检 600s、单测 1800s、分发求值 3600s。超时按「超时」单独报并中止后续步骤，不与真失败混计——
超时是超时设置与被测耗时失配，不是被测对象的结论。机器更慢时调大该值，不要放宽判据。

**第三遍不得省略**：它是《系统演进准则》第 7 节「多状态求值」的落地——同一份代码在
「已初始化本机」与「新克隆收件方」两个状态下会给出两个不同的真相，只在开发者本机求值的门禁
是单点绿灯。阻断项非空即判定本轮自检不通过。

## 2.1 自检补全（覆盖审查与补齐）

此模式由 Agent 执行；`report_selfcheck.py` 只运行既有门禁，不自动设计检查器。

1. **基线**：检查 Git 状态并先运行三遍自检，记录现有阻断、建议与未验证范围。
2. **查漏**：对照规则契约、工具实现、调用方与测试，核验检查是否真实执行、报告是否保留证据；查缺失的正常/异常、边界、初始化与分发回归，不以测试数量或函数名出现代替覆盖证明。
3. **补齐**：可机械验证的遗漏优先扩展现有检查器与最小复现测试，同步受影响调用方、报告和 Skill；不能机械判断的条目保留人工核验依据与「未验证」，不凑全覆盖。
4. **边界**：指令授权本轮范围内的控制面检查补齐与缺陷修复，按 `system-evolve` 判定形态；不扩大到业务项目整改、规则退役或外部动作，额外授权仍按根系统治理处理。
5. **复核**：重新运行三遍自检，按《根系统治理》自迭代闭环完成真源同步、测试、体检与本地提交；阻断未清零时如实报告，不宣称补全完成。

沿用第 4 节两部分报告；「验证结论」说明发现和补齐了哪些缺口及验证证据，「可优化项」仅列仍需行动的事项。没有新增缺口时如实说明，不为完成指令造新规则或工具。

## 3. 检查器边界（只证明所列形态）

九条公理都有体检项承接。无承接时报告仍标「未验证」，不得因「本轮未改动」判通过。
检查器只证明下列形态，同义改写和当次会话里的人工授权不在静态检查内：

- 第 33 项：项目入口与 Spec 的明示放宽语句；工具中的动态执行或系统外壳调用
- 第 34 项：工具引入禁用第三方依赖
- 第 35 项：零引用规则列为退役候选，不自动删除
- 第 31 项：源码未直接调用平台打开命令。自检报告默认不落盘，本轮没有打开义务
- 第 24 项：语法税超过 50% 时写明去表化这一兑现方式
- 第 30、36、37 项与分发扫描：价值回收到期、Unix 命令的 Windows 回退、工具异常路径测试、凭据特征串与家目录路径
- 业务正文和 `credentials/` 的内容不进入扫描；越界扫描由测试固定为失败

新克隆缺少词表、项目登记或实例声明时，必须留下对应建议项。没有留痕即阻断。

## 4. 产物契约

会话内输出系统自检报告，章节**严格仅保留两部分**：

1. **验证结论**：按「检查对象、证据、结论、未覆盖范围」四段式。结论只取
   **通过 / 阻断 / 未验证** 三态，不产出缺乏校准依据的数字评分。双重体检结果仅证明所列检查项；
   人工核查另列对象与依据，未核查的盲区标为未验证。
2. **可优化项**：**异常上报制**——只列举存在实质优化空间的条目，严禁罗列「维持现状」
   「无需整改」「予以保留」等无动作项目。新克隆第 13、15c、22 项的合法初始态留痕写入验证结论，不在本节重复。全项健康时直接说明本轮无待优化项。

不强制落盘报告。确有必要落盘时遵循《文件交付》第 1 节触发门禁与 2.6 节根系统研究产物归属
（`.entropaxis/data/docs/{{yyyymmdd}}_{{主题}}/`），并按第 4 节处理打开（`.md` 报告不自动打开，回复中给出路径）。
