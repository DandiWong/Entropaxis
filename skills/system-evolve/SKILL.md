复制到对话逐项打勾：

## 1 读现场（先查，后问）

1. 定动作：**增 / 改 / 删 / 查**（查 = 只分析现有能力该是什么形态，不落地）。
2. 改、删、查：定位对象当前路径与形态（`rules/`、`tools/`、`skills/`、`schemas/`、`data/`），用 `rg` 查所有引用方：根入口路由、`治理指令.md`、`tests/`、`data/rules/tips.md`、其他 Skill。
3. 增：用 `rg` 查已有规则、工具、Skill 是否已覆盖或可扩展。已覆盖即转为"改"（复用优先）。
4. 能从对话、代码、现有文件里读出的答案，第 2 步不再问。
5. 自行判定**能否机械化**：步骤能否写成固定代码、不需要语义理解或审美判断（如校验格式、算指纹、批量改名）。这一项不问用户——任何需求都要求换人、换 Agent 结果一致，一致性不是区分形态的依据，能不能用代码保证一致才是。

## 2 问答补缺

只问第 1 步没答出的；用户要求不提问或做整体盘点时跳过本步，按现场事实自判，推断处标明"推断"。每轮最多 4 问，优先用 AskUserQuestion 工具，没有就列成编号选项。问题用下面原文，选项可按场景改写举例：

**Q1 它是什么**：它更像哪一种？
- 一条规矩：不管做什么事，碰到某个动作就得遵守（如"删文件前必须确认"）
- 一套做法：要办某件具体的事时，照着一步步做（如"生成周报"）
- 一个检查：做完后让机器核一遍对不对

**Q2 用得多不多**：它会用在哪、多常用？
- 很多项目都用，或每天都用
- 只有某一个项目用
- 偶尔用一次

**Q3 专不专属**：它依赖公司/部门专属的东西吗（内部系统、模板、账号、业务口径）？
- 不依赖，任何人拿到 Entropaxis 都能用
- 依赖，只我们内部用
- 要连外部系统，但连不上也能凑合

**Q4 危不危险**（仅涉及文件或外发时问）：它会删除、批量改写文件或对外发送吗？
- 会
- 不会

**Q5 为什么动它**（仅改、删时问）：
- 它防的问题已经有工具自动检查了
- 它依赖的东西已经不存在了
- 很久没用到过
- 写得不对或不好用

## 3 判定

### 3.1 判定顺序

按序走，先命中先定；一个需求可拆成多份，各落各处，同一事实只写一处：

1. **Q2 = 某一个项目** → 局部 Script，放该项目 `03_工程研发/<app>/scripts/`，不进控制面。**Q2 = 偶尔一次** → 不沉淀，留在对话。
2. **Q3 = 内部专属** → 只能是私有 Skill（目录内 `.gitignore` 写 `*`），控制面一行不留。
3. **能机械化（第 1 步第 5 条）且 Q2 = 常用** → Tool 候选，逐条核《工具设计》第 2 节五项，任一不过就退回 4、5 两步。只服务一个 Skill 的放该 Skill 的 `scripts/`，控制面规则要调用的才进 `tools/`。**Q4 = 会** 时，Tool 必须收敛参数并提供 `--dry-run`。
4. **Q1 = 规矩** → Rule。先找现有正交规则文件并入，确无归属才新建。
5. **Q1 = 做法** → Skill。但若步骤主要在串联控制面机制（事务胶囊、注册表、打开闭环），离开本工作区就没意义 → 留在 Rule，只做编排。
6. **Q1 = 检查** → 机械可判的归 Tool（或并入 `lint_workspace.py`）；要人判断的写进 Rule 或 Skill 的质量门禁。
7. 涉及字段集、取值域、必填项 → 另加 Schema；实例参数 → 在 `data/` 声明，并写明缺失时的兜底。

常见组合：Rule 写判据，Tool 做机械检查，Skill 编排步骤。

**删**：命中《根系统治理》「规则审计流程」第 3 步退役条件的，只列候选与理由，用户拍板后才删。
**改**：先看当前形态还合不合适（见 3.2），不合适按迁移处理：新形态落地，旧处改为引用或退役。

### 3.2 该换形态的信号

- 规则里出现路径计算、正则校验、字段回填等机械步骤 → 抽成 Tool
- 规则某节越写越长、带模板，且只在一种意图下用 → 拆成 Skill，规则只留判据
- 多个 Skill 重复同一条约束 → 上收为 Rule
- 判定逻辑开始给大小写、全角等文本变体加正则 → 状态改用 YAML/JSON + Schema

### 3.3 判定单

输出给用户，**确认后才动手**；动作为"查"时到此结束：

```text
动作：增/改/删/查    对象：<名称>
结论：<主形态>（拆分：Rule <文件> / Tool <文件> / Skill <目录>）
依据：<每条一句，引用问答或现场事实>
落点：<路径>
联动：<入口路由 / 治理指令 / 测试 / tips / 其他 Skill>
不选：<排除的形态及理由>
```

## 4 按分支落地

### Rule

1. 优先并入现有文件；新建文件须与现有规则正交，并在 `.entropaxis/entrypoints/AGENTS.md` 加路由，然后执行 `python3 .entropaxis/tools/bootstrap.py`。
2. 按《表达文风》「规则瘦身」写：判据与操作分离，复述改引用；单文件超 120 行时同轮提出等量退役候选。
3. 引用 `data/` 字段时，同处写明字段缺失的兜底。

### Tool

1. 契约按《工具设计》第 3 节：`动词_名词.py`、argparse、`--json`、`❌ 错误原因` + `👉 修复建议`、默认静默与截断。
2. 以 `templates/tool.template.py` 为起点写 `.entropaxis/tools/<name>.py`：纯标准库，写入走临时目录后原子替换，不出现业务系统名、本地端点或密钥。
3. 写 `.entropaxis/tests/test_<name>.py`：覆盖正常路径、非法输入报错、`--json` 输出。
4. 在调用它的规则或 Skill 写明命令；要往 tips 加提示须先经用户确认。

### Skill

1. 先定类型：控制面 Skill（frontmatter 写 `metadata.scope: control-plane`）、可分发 Skill、私有 Skill（`.gitignore` 写 `*`，触发词只写在自身 description，控制面不设路由）。
2. 目录、元数据按《技能设计》2.2 与第 3 节：`SKILL.md` ≤500 行、`CHANGELOG.md` 必备、参考资料单跳引用、description 写清做什么与何时触发。
3. 指导方式按《技能设计》1.2 选：启发式清单 / 参数化模板 / 确定性脚本。
4. 可分发 Skill 不读写 `.entropaxis/data/`，不把 `.entropaxis/tools/` 当必需步骤；工作区能力按"有就用、没有就降级"接入。
5. 生成文件的 Skill，尾部带《文件交付》第 4 节的打开闭环。
6. 需要评测触发率时，已安装 `skill-creator` Skill 就借用其评测流程；没装则跳过并在交付中说明。

### 删除

用户确认后：删文件 → 用 `rg` 清掉第 1 步查到的全部引用 → 改了路由就同步入口并执行 `bootstrap.py`。

## 5 收尾

按《根系统治理》「自迭代闭环」五步执行，体检命令：

```bash
python3 -m unittest discover -s .entropaxis/tests -t .entropaxis
python3 .entropaxis/tools/lint_workspace.py
```

回复写明检查对象、证据、结论（通过/阻断/未验证）、未覆盖范围；精确 `git add` 本次文件后提交，不推送。
