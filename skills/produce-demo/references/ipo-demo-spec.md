# IPO 交互 Demo 设计规范与过度设计裁剪指南

本参考文档详述界面信息架构、交互组件与裁剪判据。

---

## 一、 IPO 三栏信息架构标准

```text
┌───────────────────┬─────────────────────────────────────┬────────────────────────────────────────────────────────┐
│ 1. INPUT (280px)  │ 2. PROCESS (自适应 1fr)              │ 3. OUTPUT (630px 宽屏呼吸感)                            │
├───────────────────┼─────────────────────────────────────┼────────────────────────────────────────────────────────┤
│ • 来源文件卡片     │ • 阶段动作主按钮 (▶ 启动智能处理)      │ • 初始状态: Empty State 空状态占位                     │
│ • 上阶段继承提示   │ • 处理进度微动效 (Spinner/Progress) │ • 结果呈现: 结构化表格 / 抽屉明细 / 规则卡片            │
│ • 点击 Mock 状态  │ • 人话提示语输入卡片 (暖黄气泡)      │ • 宽屏排版: 拒绝多列文字折行，留足行距与列宽           │
│                   │ • 逻辑表达式代码块 (深灰等宽代码)    │                                                        │
│                   │ • 解锁下一步按钮 (完成操作后高亮)    │                                                        │
└───────────────────┴─────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

### 1.1 CSS 栅格契约
```css
.ipo-grid {
  display: grid;
  grid-template-columns: 280px minmax(340px, 1fr) 630px;
  gap: 20px;
  align-items: start;
}
```
- **左栏 Input（280px）**：收敛外部输入文件卡片与继承提示，保持紧凑；
- **中栏 Process（自适应 1fr）**：承载核心操作、参数与控制动作；
- **右栏 Output（630px）**：宽屏排版，彻底消除字段列表、规则明细的多列折行拥挤问题。

## 二、 交互细节规范

### 2.1 初始空态（Empty State）与渐进点亮
- 首屏打开页面时，所有阶段的内容区默认显示干净的 Empty State 占位（浅灰虚线边框、微弱图标、简短引导文字）；
- 严禁一进入页面就堆满静态数据，破坏“从无到有”的操作真实感。

### 2.2 点击快速 Mock 切换（演示利器）
- 输入卡片初始显示为“未上传（轻点载入脱敏样本）”；
- 演示时无需去本地文件系统寻找文件，用户单击卡片即刻切换为“✔ 脱敏样本已就绪”的高亮实线状态；
- 兼顾业务真实感与现场汇报的高效性。

### 2.3 上下游流水线数据继承
- 阶段 2~N 进入时，在 Input 栏顶部自动渲染继承提示：
  `✔ 已继承上一阶段产出成果：XX 表单与 YY 字段已就绪`；
- 前序阶段未完成时，后序阶段 Stepper 必须置灰锁定，阻止越级跳转。

### 2.4 文案“讲人话”标准
| ❌ 晦涩研发黑话 | ✅ 临床与业务一线人话 |
| :--- | :--- |
| `System Generated Query Message` / `触发自动下发的 Query 提示语` | **`录入报错提示语（数据录错时，弹给医生或 CRC 看的话）`** |
| `DVP Rule Logic AST Execution` | **`数据核查逻辑表达式（满足此条件时触发报错）`** |
| `Baseline Diff Conflict Resolution` | **`专家审核与排错工作台（确认规则是否有矛盾或遗漏）`** |

## 三、 过度设计外科手术式裁剪清单

在出具 Demo 前，必须对照以下 4 个维度进行减负：

1. **是否在重复造客户既有系统的轮子？**
   - 裁减：智能体终局产物停在“生成并导出标准配置 Excel”，不重复做成熟系统的录入端。
2. **是否加入了给工程师看的黑框终端（Terminal）？**
   - 裁减：拿掉 `$ python ...` 终端滚屏黑框，改为贴近业务软件的进度条或分步步骤卡片。
3. **是否生搬硬套大而全的学术标准？**
   - 裁减：在缺乏专职团队的场景中，不做强制复杂的标准映射，只要字段能对齐即可。
4. **是否违规引入了动态反哺改写规则？**
   - 裁减：严守规范，锁定 V1.0 基线不可篡改，剔除未经人工审核的自动动态反哺。
