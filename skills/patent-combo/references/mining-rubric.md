# 代码挖点评分 Rubric（Stage 1）

> 借鉴 mascher/invention-mining 方法论，适配中文交底流程。原则：**描述性、不下法律结论**——只刻画技术贡献，不说"可专利/新颖"。

## 扫描范围（发明藏在哪里）

优先级从高到低：
1. 核心引擎/算法（排序、调度、推理、匹配、压缩、加密…）
2. 自定义数据结构与存储方案
3. 跨系统 distinctive 集成点（协议适配、异构数据融合）
4. 性能/成本优化的非常规手段

**跳过**：样板代码、CRUD 胶水、测试、配置、纯 UI 布局、直接调第三方库无增量封装的部分。

## 四维评分（0–12 分，≥10 自动进入撰写）

| 维度 | 0–1 分 | 2 分 | 3 分 |
|---|---|---|---|
| 独特性 distinctiveness | 常见做法 | 有个人化变形 | 同类问题里未见公开同款 |
| 复杂度 sophistication | 平铺直叙 | 多层协同 | 非平凡设计权衡（trade-off 明确） |
| 系统影响 impact | 局部细节 | 影响一个子系统 | 影响整体架构或业务指标 |
| 视角迁移 frame shift | 无 | 换个角度看问题 | 引入跨领域思路解决本领域问题 |

每个候选必须附：
- **代码证据**：文件路径 + 关键函数/类（保持抽象层级：写发明构思，不绑死单一实现，但留代码引用支撑）；
- **置信说明**：为什么可能不是发明（counter-case）；
- **发明人归因**：`git blame -L` 关键行 + `git log --follow` 主要提交者；
- **设计动机**：从 commit message / 注释 / DESIGN 文档挖掘"当时为什么这么做"；
- **披露时序**：代码是否已开源/已公开发布（影响新颖性宽限期，仅提示不定论）。

**自动路由**：得分 ≥10 的候选全部自动进入 Stage 2–4；得分 <10 的候选不进入撰写。不得为候选列表停下来等待用户勾选、裁决或补充 know-how。若无候选达到 10 分，报告“无自动入选候选”后结束本轮。

## 产出格式

`01_候选清单.md`：按总分倒序，每项含上表全部字段 + 建议类型（发明/实用新型/外观）+ 建议追问清单（代码里挖不出的 know-how，供 Stage 2 访谈用）。
