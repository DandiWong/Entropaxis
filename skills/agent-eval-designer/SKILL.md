# Agent Eval Designer

## Overview

为任意 AI/Agent 产品设计完整的评估体系。核心原则：评测即需求——AI 产品的需求不再只写在 PRD 里，而是写在 Sample + Rubric + Metric 里。通过 8 步流程，从 Task 边界定义到运营闭环，输出一套可执行、可追踪、可迭代的评估方案。

## 完整方法论参考

详细的方法论 Playbook（含完整模板、公式速查、示例、空白工作表）存储在：
`references/playbook.md`

在执行任何步骤前，先读取该文件获取详细指导和模板。

## Grilling 机制（核心执行方式）

本 Skill 采用 grilling 机制——通过 relentless 提问将评估设计过程收敛到精确方案。以下规则不可违反：

### Grilling 规则

1. **一次只问一个问题。** 连续抛出多个问题会让用户无法深入思考。每问一个，等用户回答后再问下一个。

2. **沿决策树逐分支推进。** 8 步流程中每步都有若干决策点，按依赖关系排序，逐个解决。前一个决策的结果会影响后一个决策的选项。

3. **每个问题附带推荐答案。** 不盲目提问——基于已读取的 Playbook、用户提供的产品信息和环境中的事实，给出推荐选项及理由。用户可以接受、修改或拒绝。

4. **能从环境查到的事实不问用户。** 先读取用户提供的文件（benchmark、PRD、需求文档、已有测试数据等），从中提取事实。只把需要用户判断的决策抛给用户。

5. **决策权归用户。** 每个决策点给出推荐后，等待用户确认或修正。不替用户做决定。

6. **未达成共识前不输出最终方案。** 所有决策点解决后，先向用户展示方案摘要，确认"我们对评估方案的理解一致"后，再输出完整文档。

### Grilling 执行流程

```
Phase 0: 环境扫描
  → 读取用户提供的所有文件（benchmark/PRD/需求文档/测试数据）
  → 读取 references/playbook.md 获取模板
  → 提取事实：产品类型、已有数据、覆盖状态、依赖知识等
  → 识别需要用户决策的关键问题
  → 向用户展示扫描摘要 + 即将开始的 grilling 计划

Phase 1-8: 逐步 Grilling（每步包含若干决策点）
  → 按 Step 1-8 顺序，每步内部按决策点依赖关系排序
  → 每个决策点：展示问题 + 推荐答案 + 推荐理由 → 等用户确认
  → 用户确认后记录决策结果，进入下一个决策点
  → 某步所有决策点完成后，展示该步小结 → 进入下一步

Phase 9: 方案确认
  → 展示完整方案摘要（所有决策结果汇总）
  → 确认"我们对评估方案的理解一致"
  → 用户确认后输出完整评估工程方案文档
```

## 决策树（8 步 × 关键决策点）

## 8 步流程概要

### Step 1 · 明确 Task 边界
填写 Task 定义模板：Task 名称、能力描述、输入规格、输出规格、典型场景（3-5个）、禁止行为与红线（逐条列出）、关联评测。核心：红线用"出现即 fail"句式。

### Step 2 · 构建 Dataset
设计 Sample 最小结构（user_profile + context + query + expected_output）+ 三层场景分布（高频/高风险/多样性）+ 来源计划。自检：评分人能否独立判断？

### Step 3 · 设计 Rubric
三层结构：红线（触犯即 fail）+ 质量维度（1-5 分，写清锚点）+ 体验偏好（权重低）。通用维度：即时满足/信任度/信噪比/安全性。准备 10-20 条校准 case。

### Step 4 · 选择 Metric
四种汇总形态：红线违规率/召回率/维度均分/通过率。按任务类型选指标。组合：守门+能力+感受。必须支持切片。阈值：红线倒推/基线/业务反推。

### Step 5 · 选择 Judge
四种 Judge：规则程序（客观封闭）/ LLM Judge（开放输出规模化）/ 人工评审（校准锚点）/ 专家评审（高合规+金标准库）。注意三个偏见：位置/冗长/自我偏好。

### Step 6 · 配置 Protocol
锁定 Judge 模型版本、Few-shot 示例、温度/采样、联网/工具、盲评、校准频率、成本预估。反模式：用被测模型评自己/无版本号/从不人工抽样。

### Step 7 · Agent 专项
eval trace 三层：步骤级（工具/参数/结果解读）+ 轨迹级（路径效率/死循环/自我纠错）+ 结果级（目标达成）。Dataset：Goal-only 或 Golden Trace。多轮：全链路整体评或 User Simulator 逐轮评。

### Step 8 · 运营闭环
bad case 回流管道 + Dev/Test 分离 + 离线-线上拟合 + 三层评测节奏（CI/迭代/上线）+ 报告三层受众 + 健康检查 9 项。

## 跳过规则

- 如果用户只需要评估体系的某个部分（如只设计 Rubric），直接跳到对应步骤的决策点
- 如果用户提供的文件已经包含了某步的答案（如 benchmark 已含通过标准），跳过该步的已知决策点，只问未覆盖的
- 如果某步不适用（如产品不是 Agent，跳过 Step 7），告知用户并跳过
- 如果用户明确说"按你的推荐来"，可以跳过该决策点的提问，直接采用推荐答案并标记"按推荐"
